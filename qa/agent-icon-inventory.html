目前真正要改的几处

头像颜色没有接通

AgentIcon 当前用 img 加载 SVG；对象里的 icon.color 没有参与渲染。旧 SVG 内部也写有固定色和渐变，外部 color 无法直接染色。

编辑保存会丢掉颜色

表单只有 iconKind / iconName / iconImage。iconFieldsFromValue 不读取 color，buildIconValue 只重建 name，所以需要一起补齐颜色读取、草稿、预览和保存。

多数入口没有传智能体 mode

AgentIcon 的 type 仅支持 agent，无法区分六类。侧栏的图标映射也只传 icon，需要把 mode 或归一化后的身份展示信息一并传下去。

导出是独立的一条链

分享文档直接取旧 SVG；快照主要保留 iconName，缺少 mode / color。迁移需要同步导出投影，并让旧快照继续可读。

最终方案：图标与类型独立，再选颜色

查看六类默认造型提案 →

六类共用眼睛和表情。执行型已采用双斜线穿梭，代理型已采用委托窗口；团队前脸放大，后排保留外侧半弧。

创建时由类型给出默认图标；之后六款图标与颜色均可独立选择。

导航、列表和头像保持静态；运行中的 activity 才使用随机表情和轻快小动作。同一个智能体在所有位置使用同一轮廓、同一颜色。

实现顺序

  1. 先建立共享的图标底座把目前 timeline 内的小脸几何与类型映射移到 shared/icons；静态头像和动态 activity 都复用它，避免 shared 反向依赖 feature。
  2. 接通完整的颜色编辑链读取 → 草稿 → 实时预览 → 保存 → 重新加载。沿用已有 icon.color 字段，验证 Platform 确实接受并保留它；不按旧 icon.name 猜测业务类型。
  3. 统一所有展示入口给 AgentIcon 传 mode 和 icon；补齐侧栏缓存与精简投影丢掉的 mode / color。采用 inline SVG currentColor，兼容已有尺寸与样式。
  4. 最后迁移旧入口与导出编辑器移除 31 款旧图案的选择入口。旧 name 不主动批量改写；外部图片先保留兼容。导出补齐类型与颜色，旧资产等无直接依赖后再清理。
