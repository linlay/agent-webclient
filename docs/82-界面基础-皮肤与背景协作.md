# 皮肤与背景协作

## 责任与模型

`features/appearance` 集中管理明暗偏好、皮肤定义、资源恢复、文档变量和组件库主题。`AppState.themeMode` 只投影最终 light/dark，继续供编辑器、终端等原有明暗消费者使用，不再负责保存外观。专业终端调色板、预览 iframe 正文、导出与匿名分享不接入皮肤变量覆盖。

外观分为三层：

- 偏好：Standalone 的 light / dark / system，沿用 `agent-webclient.themeMode`，兼容旧 light/dark 值。
- 皮肤：default、mist（薄雾）或导入包；受控 Desktop v1 语义 token，不接受任意 CSS。
- 页面背景：standalone、host、host-fallback。`DESKTOP_APP` 只接受布尔 true 或精确字符串 `"true"`。只有 Desktop 模式且收到有效快照的 `background.mode="host"` 才透出宿主壁纸。

`--bg-base` 始终为不透明、安全的颜色基底；`--page-bg` 单独决定 html 的整页背景。body 装饰层只用于 Standalone 图片与皮肤遮罩，pointer-events 为 none，不参与布局。宿主模式不分发、复制、缓存或 cover 裁切 Desktop 照片。

New Chat 空态使用独立的 `--new-chat-surface`：有宿主壁纸或 Standalone 图片时，浅色模式使用皮肤正文底色的 6% alpha，黑夜模式使用 `rgba(64, 64, 64, 0.06)`，保持几乎透明，让背景清晰透出；无图片或宿主能力失效时恢复实色。取得 chatId 后（包括 live stream、完成后的对话与历史会话）沿用阅读遮罩，不随流式开始或结束反复切换透明度。New Chat 输入框与 Wonders 推荐卡片使用独立的 `--new-chat-input-surface`，有图片时保留 64% 不透明输入底色，轻微透出背景；文字与子控件不设置 opacity。无图片时保持原输入底色。

已有会话主聊天使用 `--main-chat-surface`，在有背景图片时，浅色模式对皮肤 `--shell-content-bg` 设置固定 82% alpha，黑夜模式使用 `rgba(16, 16, 16, 0.72)`。`AppLayoutCompat.module.css` 在两个主聊天壳层的第 2 列后方放置贯穿所有行的遮罩，覆盖顶部、正文、两侧留白和输入区；照片透过遮罩显示，不随消息长度或滚动改变覆盖范围。正文阅读列、加载骨架和空会话标题不再叠加局部阅读底板。遮罩不接收指针事件，也不给内容设置 opacity。

智能体、技能中心、连接器中心、注册配置、自动化和已归档对话页面使用统一的 `--management-page-surface`：有宿主壁纸或 Standalone 图片时，以皮肤正文底色的 94% alpha 覆盖整个页面，包含工具栏、列表、详情与留白；即使皮肤提供实色正文底色，仍保留淡淡的照片。宿主能力失效或无图片时恢复不透明底色，不改变 `--bg-base`，不对页面内容设置 opacity。列表悬停与选中分别使用 hover / selected 语义颜色。

共用 CodeEditor 通过共享主题 Context 接收 AppearanceProvider 解析后的皮肤配色，映射 Monaco 的阅读背景、文字、行号、当前行、选区、光标和滚动条；语法高亮继承对应明暗基础主题。皮肤更新只重新定义编辑器主题，不重建编辑器或模型，保留草稿、撤销历史和光标。

Composer 与 wonders 卡片使用独立输入面，代码块保持自己的底色。皮肤适配只调整颜色、对比度与背景合成，不改变控件尺寸、间距、圆角、字号、图标和交互。Copilot、Overview/Debug 与独立 Surface 继续使用 `--reading-surface` / `--panel-surface`。按钮、输入框、菜单和弹窗有独立状态；浮层和普通输入底色合成到安全基底；New Chat 输入框与 Wonders 卡片仅在有图片时按上述 64% 不透明度轻微透出背景。

## 单一颜色来源与首屏

默认明暗值在 `shared/styles/appearance/tokens.css`；旧 `--bg-elev-*`、`--ink-*`、`--accent-electric` 等变量成为兼容别名。皮肤在 documentElement 上覆盖受控语义值，退出或切回默认时移除旧覆盖，保留不属于外观层的内联属性。

`AppearanceProvider` 在写入文档变量后发布状态，`antdTheme.ts` 读取解析后的 CSS 生成 ConfigProvider 配色，包括 primary hover/active、disabled、Input/Select、Tooltip、Dropdown、Modal/Drawer。深色算法保留皮肤已解析主色。body portal 继承同一 Provider；需要确认交互的管理功能使用 `AntdApp.useApp().modal`，不能重建独立无主题的静态 Modal 根。

Webpack 把无依赖 `bootstrap.ts` 的同一份解析代码嵌入 HTML。`runtime-config.js` 先加载，再执行主题解析；关键 token CSS 提前内联。有效 URL `theme` 优先于 `hostTheme`，非法参数忽略；Standalone 再读取持久偏好和系统明暗，Desktop 缺少 URL 时只用系统回退，不使用 Standalone 偏好。React 使用同一 resolver，URL 和宿主临时颜色都不落盘。

有效宿主快照优先于所有 URL 明暗。宿主失效时撤销透明，保留最后验证过的明暗/皮肤颜色作为实色回退。已安装图片从 IndexedDB 异步恢复，图片就绪前保留匹配明暗的实色，不等待图片阻塞业务。错误边界位于外观 Provider 内，业务渲染失败后仍继续消费外观。

## Standalone 设置与资源

设置中的「外观与皮肤」提供主题选择、皮肤选择、ZIP 导入/删除和 PNG/JPEG 背景导入/恢复。选择皮肤不会清除自定义背景；「恢复皮肤背景」重新显示皮肤自带图片。导入包先加入列表，再由用户选择应用。

`agent-webclient.appearance.v1` localStorage 只保存所选 skinId。图片 Blob 与安装包保存在同名独立 IndexedDB；Desktop 模式完全不打开该数据库、不安装宿主资源。存储失败保留旧资源并提示错误；资源缺失、损坏或图片解码失败回退默认皮肤、内置背景或实色。自定义图片身份改变可以恢复，迟到图片加载不会覆盖后来选择。

包格式与 Desktop 相同：根目录 skin.json，schemaVersion 1，id/name/version，variants.light/dark，受控 tokens 与包内 PNG/JPEG background/preview。JSON 元数据与用户图片均不作为代码执行。Standalone 使用包 manifest id 标记 `pack:<manifest-id>`，Desktop 安装时生成的本地包 id 不互相复制。

限制与验证：

- ZIP ≤32 MiB、展开总量 ≤48 MiB、单文件 ≤16 MiB、manifest ≤64 KiB、最多64条目/20个安装包。
- 先检查 ZIP 中央目录，再有界流式解压，拒绝 ZIP64、加密、软链接、重复或不安全路径、脚本及非图片额外文件。
- 路径拒绝绝对路径、盘符、反斜线、`..`、URL、Windows 保留文件名和歧义后缀。
- 颜色仅 hex / rgb / rgba / transparent；四个圆角 0–32px；disabled opacity 0–1。任意 CSS 函数、脚本、外部 URL 不合法。
- PNG/JPEG 先验签名与尺寸，再解码；≤16 MiB、单边≤8192、总像素≤2400万。照片不写入 localStorage。

## Desktop 外观桥 v1

消费 canonical generated `AgentWebclientAppearanceBridge` / `parseAgentWebclientAppearanceSnapshot`。它独立于现有 WorkPanel v6、Platform Frame Port v2 和 routeRevision，新增外观不改变业务协议版本。

preload 暴露固定只读全局 `__AGENT_WEBCLIENT_APPEARANCE__`：

```ts
interface AppearanceBridge {
  readonly version: 1;
  getSnapshot(): Promise<AppearanceSnapshot | null>;
  subscribe(listener: (snapshot: AppearanceSnapshot | null) => void): () => void;
}
interface AppearanceSnapshot {
  schemaVersion: 1;
  revision: number; // 同一 guest 文档中单调增加的正安全整数
  resolvedTheme: 'light' | 'dark';
  skinId: string; // 1–96 字符，首字符字母或数字，其余为字母数字 . _ : -
  tokens: Record<string, string>; // 最多47个白名单 token
  background: { mode: 'host' | 'opaque' };
}
```

颜色42项、圆角4项、disabled opacity1项与 Desktop ZIP v1 对齐；`--accent-rgb` 等衍生 CSS 表达式不跨桥发送。快照必须是完整对象，不接受额外顶层或 background 字段。宿主在投递之前将自己的 CSS 表达式解析成受控颜色。

guest 先订阅再读取，读取超时2秒。较旧 revision 和同 revision 的冲突快照丢弃；同 revision 相同快照允许在失效后恢复。null、非法快照、读取错误/超时、bridge 消失都会撤销透明。晚到的 bridge 每秒轻量探测一次；pageshow 与隐藏恢复重新读取。每次读取带本地序号，订阅已更新或 observer 释放后，迟到读取不再覆盖页面。

仅可信 preload 能提供桥。WebClient 不接收任意窗口的 postMessage 外观，不使用业务 Frame Port、不更新 URL、不发送路由 ACK、不改变会话身份、不 reload。现有 URL 主题仅保留首次启动与旧宿主兼容；最新 Desktop 只有确认 guest 消费新桥后才停止旧 URL 主题同步。

此前静态讨论提出的 URL/revision 冲突不能直接认定为已复现缺陷。当前源码仍以 Router READY/APPLIED 确认业务导航；外观实现完全绕开这条通路，隔离 Electron 测试验证换肤时 URL 与 guest 身份不变。

2026-09-10 隔离验收：真实 Service WebView preload/contextBridge、Desktop 生产 relay/projection 与本演示已联通。macOS 环境中验证 macOS/Windows 两套 CSS × 明暗的主聊天照片透出；草稿、演示附件、消息滚动、流式计数、审批状态、React mount identity、guest ID 及审批 Modal 的输入/焦点跨换肤保持。null 回退与 relay 重建恢复通过。Copilot/Panel 为 opaque。Standalone 实测 Desktop 山湖 ZIP 导入、应用与刷新恢复。
