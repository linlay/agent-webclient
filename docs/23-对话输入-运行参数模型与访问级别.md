# 运行参数模型与访问级别

## 当前状态
Composer 的运行参数包含 access level、模型覆盖、reasoning effort、service tier、planning/editing mode 和单次 must-use skills。通用控件由 `QuerySettingsControls` 承载，Mode 从 Composer “+”菜单选择，Skills 从 slash palette 选择。

## 核心职责
- 展示并持久化当前对话或当前 agent 的模型选择。
- native 模型的 reasoning effort 统一为 `NONE / LOW / MEDIUM / HIGH / XHIGH / MAX`，默认 `MEDIUM`。
- 为允许模型选择的 Agent 加载模型选项并处理默认模型覆盖。
- Composer 模型子菜单的模型列表表头提供手动刷新入口，强制重新请求 `/api/model-options` 并忽略 Agent 内嵌 `modelOptions` 与前端缓存；刷新失败保留原列表并在模型按钮旁提示。
- 将 access level、model override 和控制参数随 query payload 发送。
- Mode 按智能体类型显示：`CODER` 提供 Planning，`KBASE` 提供 Editing，普通 Agent 与 Team 不显示 Mode 分组。
- Slash Skills 通过 `/api/skills` 展示当前 Agent 已配置 Skill 与有效技能市场 Skill，支持单条消息多选；Team 不加载或展示该分组。
- `mustUseSkills` 进入 `/api/query` 的 SSE/WebSocket payload；发送进入 query 链路后清理，切换智能体时同步清理，旧 `requiredSkillKeys` 不再发送。
- 在运行中支持访问级别调整；Composer 权限偏好按 Chat / New Chat Agent 独立保存，不修改 Agent 配置。

## 核心流程
选中 Agent 后加载详情及解析后的 interactionConfig；详情未就绪时关闭对应入口。Composer 打开运行参数控件时加载模型选项；输入独立 slash token 时按当前 Agent 加载 `/api/skills`，Platform 通过同名 WS request 严格请求，Gateway 因能力表未开放该 route 而静态使用 HTTP，WS 传输故障不回退。选中 Skill 后清除 slash 查询并生成可逐项移除的“必须使用”标签。发送消息时，`buildControlsParams`、`modelOverride`、`accessLevel`、mode 和 `mustUseSkills` 被传入发送事件，最终由 `buildQueryPayload` 写入 `/api/query` 请求。reasoning effort 在 Composer 自定义事件、BTW、HTTP/SSE 与 WebSocket payload 中统一归一为大写逻辑值；兼容输入 `EXTRA_HIGH` 归一为 `XHIGH`，前端不执行 provider 模型翻译。若 @mention 或最终路由智能体与选择来源不一致，前端阻止发送。运行中调整 access level 时调用 data client，并用当前 `RunOwner` 序列化身份：所有 Agent（包括 TEAM）都发送根 `agentKey`。

## 边界与非目标
- 前端只展示后端返回的模型与权限能力，不自行推断真实权限。
- 模型、权限级别、必用技能、连接器、本地文件和聊天记录入口消费 `/api/agent.interactionConfig`。REACT 默认全开，CODER 默认关闭聊天记录，KBASE 默认关闭模型、权限级别、连接器和聊天记录。配置缺省按后端 mode 默认值解析；无网盘文件字段。
- must-use skills 是单次、多选约束；Agent 已配置与技能市场项都可选，最终可用性由 Platform 校验，Team 不提供选择入口。
- 模型参数只作为请求提示，最终执行语义由后端决定。

### 模型可选项与已选值

`/api/model-options` 只提供 `models`、`reasoningEfforts`、可选 `serviceTiers`，不返回选择或 default 字段。`/api/agent` 使用顶层 `modelKey/reasoningEffort/serviceTier`；NONE 表示关闭思考，未配置服务等级省略字段。详情不再返回 `model`、`selected*`、`modelConfig`、`modelOptions` 或 meta 中重复的模型信息，ACP 详情不请求上游能力、不自动替换配置的 modelKey。模型暂时不可用时前端保留配置并提示，不自动选其他模型。

Native 的 `models` 项仅消费 `key/name/icon/provider` 与可选 `serviceTiers`；不依赖 `modelId/protocol/isReasoner/isVision/contextWindow/timeout` 或模型级 `reasoningEfforts`。模型一致性诊断在没有 `modelId` 时使用 key/provider。ACP 模型保留原有发现字段，Agent 编辑页仍从 `/api/admin/agents/editor-options` 读取模型级思考能力。顶层 `reasoningEfforts` 保持 `{key,label}` 对象数组，菜单优先使用客户端翻译，未命中时保留服务端 label（包括中文）。

`POST /api/agent/model-config` 只接受 `agentKey`（必填），以及至少一个 `modelKey/reasoningEffort/serviceTier`；省略设置保持原值，`serviceTier:null` 清除等级。响应为扁平 `{agentKey,modelKey,reasoningEffort,serviceTier?}`。不接受 key 别名和未知字段。选项缓存和手动刷新只更新能力列表。New Chat 的模型选择在保存成功后更新 Agent 默认配置；已有 Chat 的模型选择只更新该 Chat 的 Composer 偏好，不调用此接口。

`/api/agent.skills` 为 `{id,displayName}[]`，无技能时为空数组；管理编辑器转换为 id 数组写入 `definition.skillConfig.skills`，内部 YAML 结构不变。`meta.perAgentSkills` 已移除。

`interactionConfig` 是 `/api/agent` 返回的输入能力配置，不属于 `/api/query` 请求或 `request.query` 事件，也不从 Chat JSONL 的 `query` 恢复 Composer 能力。发送时仅提交用户实际选择的 `model`、`accessLevel`、`mustUseSkills`、`references` 等字段。Platform 将跨进程恢复所需策略快照保存在私有状态目录；旧版 JSONL 中多出的 `query.interactionConfig` 是旧服务端写入，不能据此扩展公开 query 契约。


### Access level 的会话隔离

Composer 的 access level 由 `features/composer/lib/composerAccessLevel.ts` 管理：已有 Chat 按 chatId 保存；New Chat 按 agentKey 保存，各 Agent 的新会话偏好互不影响。加载已有 Chat 时，由 `features/runs/lib/accessLevel.ts` 读取当前活动根 Run 或最近一次根 Run 的服务端权限记录（`request.query.accessLevel` 与 `run.access_level.changed`）；活动 Run 同步实际档位，已完成 Chat 仅在没有本地偏好时初始化。缺少有效权限记录和本地偏好时使用 `default`，不继承当前 Agent 的 New Chat 偏好。切换 Chat 或 Agent 直接读取目标值，不复用组件本地权限状态。

通过 `chat_start`、Automation 或其他客户端创建的 Chat 也沿上述加载路径恢复权限。实时 query/start 和权限变更事件更新当前 Chat 的展示，按权限版本忽略重复及过时事件；其他 Chat、子任务、BTW 与解读事件不提供主对话权限。同步只投影服务端数据，不调用权限修改接口；当前后端未提供活动 Run 权限快照时，恢复使用已返回的事件记录。

首次 query 获得 canonical chatId 时，将发送时的实际 access level 初始化到该 Chat，包含附件上传预先分配 chatId 的情况；后续身份事件不覆盖已有选择。该 Chat 之后修改权限不回写 Agent 的 New Chat 偏好。运行中仍通过现有 `/api/access-level` 请求修改当前 Run，失败回滚绑定原 Chat，同一作用域的旧请求结果不覆盖新选择。Agent 能力关闭或详情尚未加载时，发送使用 `default`，不删除记住的偏好。

两份偏好通过前端 `sessionStorage` 保存，Platform 与 Gateway 均支持同窗口刷新恢复，按后端模式及身份分隔，浏览器同源存储提供站点隔离。Gateway 使用用户 subject，Desktop 使用宿主 auth context，独立 Platform 使用访问凭据指纹（凭据变化后使用独立偏好）。这不是服务端权限配置，不写入 `agent.yml`，不调用 Agent 配置更新接口，也不提供跨设备同步。


### 模型与思考强度的会话隔离

已有 Chat 的模型、reasoning effort 和 service tier 按 Chat 保存，New Chat 按 Agent 保存；切换会话直接读取目标值。加载旧 Chat 时优先保留该 Chat 的本地选择，否则从最近一次主 Run 的 request.query.model 恢复，并用同 Run 的 usage.snapshot 或详情用量快照补齐实际模型与思考强度；子任务、BTW、解读及其他 Chat 的事件不参与。记录未携带模型信息时只能显示当前 Agent 默认值，前端不猜测历史配置。

New Chat 选择仍保存到 Agent 默认配置，但不会覆盖已有 Chat 的选择或历史模型；已有 Chat 的调整作为下一次 query 的 model 发送，不写 Agent 配置。首个 query 取得 canonical chatId 时绑定发送时的模型，重复身份事件不覆盖之后的手工选择。模型能力暂未加载或被关闭时，不清除偏好，发送仍遵守 interactionConfig。

偏好使用 sessionStorage 按后端与身份隔离，支持同窗口刷新；尚未发送的调整不跨设备同步。保存 New Chat 默认值的异步响应绑定原目标，切换到旧 Chat 后不会把新值写入旧 Chat。
