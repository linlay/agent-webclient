# 运行参数模型与访问级别

## 当前状态
Composer 的运行参数包含 access level、模型覆盖、reasoning effort、service tier、planning/editing mode ；技能以 references 统一引用。通用控件由 `QuerySettingsControls` 承载，Mode 从 Composer “+”菜单选择，Skills 从 slash palette 选择。

Composer 操作栏按自身可用宽度响应：小于 500px 时，模型与思考强度入口合并为一个大脑图标，隐藏文字、速度图标和下拉箭头；权限入口也只保留当前权限图标，隐藏文字和下拉箭头，两者使用相同尺寸的图标按钮。悬停说明保留当前权限、模型和思考强度，点击仍打开各自原有的设置菜单。宽度恢复后显示原有文字和下拉箭头，运行中的禁用规则保持一致。

紧凑模式的大脑按钮使用独立 Tooltip，只显示当前模型和思考强度两项；运行中或保存中按钮禁用时，由外层容器继续响应悬停和键盘聚焦以展示提示，按钮仍不可点击，也不会打开设置菜单。

## 核心职责
- 展示并持久化当前对话或当前 agent 的模型选择。
- native 模型的 reasoning effort 统一为 `NONE / LOW / MEDIUM / HIGH / XHIGH / MAX`，默认 `MEDIUM`。
- 为允许模型选择的 Agent 加载模型选项并处理默认模型覆盖。
- Composer 模型子菜单的模型列表表头提供手动刷新入口，强制重新请求 `/api/model-options` 并忽略 Agent 内嵌 `modelOptions` 与前端缓存；刷新失败保留原列表并在模型按钮旁提示。
- 将 access level、model override 和控制参数随 query payload 发送。
- 四种 Native Agent 均提供 Workspace 编辑开关，显式 true/false 保留到顶层 editingMode；未调整时省略字段，使用模板默认值（KBASE 只读，其他可编辑）。Planning 与编辑为独立入口；Planning 当前仍仅在 CODER 界面显示，该遗留限制待 mode 功能审查。
- Slash Skills 通过 `/api/skills` 展示当前 Agent 已配置 Skill 与有效技能市场 Skill，支持单条消息多选；Team 不加载或展示该分组。
- skill 定位信息随 `references` 进入 `/api/query` 的 SSE/WebSocket payload；发送进入 query 链路后清理，切换智能体时同步清理，旧 `requiredSkillKeys` 不再发送。
- 在运行中支持访问级别调整；Composer 权限偏好按 Chat / New Chat Agent 独立保存，不修改 Agent 配置。

## 核心流程
选中 Agent 后加载详情及解析后的 interactionConfig；详情未就绪时关闭对应入口。Composer 打开运行参数控件时加载模型选项；输入独立 slash token 时按当前 Agent 加载 `/api/skills`，Platform 通过同名 WS request 严格请求，Gateway 因能力表未开放该 route 而静态使用 HTTP，WS 传输故障不回退。选中 Skill 后清除 slash 查询并生成可逐项移除的统一引用标签。发送消息时，`buildControlsParams`、`modelOverride`、`accessLevel`、mode 和 `references` 被传入发送事件，最终由 `buildQueryPayload` 写入 `/api/query` 请求。reasoning effort 在 Composer 自定义事件、BTW、HTTP/SSE 与 WebSocket payload 中统一归一为大写逻辑值；兼容输入 `EXTRA_HIGH` 归一为 `XHIGH`，前端不执行 provider 模型翻译。若 @mention 或最终路由智能体与选择来源不一致，前端阻止发送。运行中调整 access level 时调用 data client，并用当前 `RunOwner` 序列化身份：所有 Agent（包括 TEAM）都发送根 `agentKey`。

## 边界与非目标
- 前端只展示后端返回的模型与权限能力，不自行推断真实权限。
- 模型、权限级别、必用技能、连接器、本地文件和聊天记录入口消费 `/api/agent.interactionConfig`。REACT 默认全开，CODER 默认关闭聊天记录，KBASE 默认关闭模型、权限级别、连接器和聊天记录。配置缺省按后端 mode 默认值解析；无网盘文件字段。
- skill references 是单条消息指定的多选资源；普通 Native Agent 已配置技能与技能中心项都可选，最终可用性由 Platform 校验。TEAM 总控支持引用，ACP/PROXY/CHANNEL 不支持本地资源定位。
- 模型参数只作为请求提示，最终执行语义由后端决定。

### 模型可选项与已选值

`/api/model-options` 只提供 `models`、`reasoningEfforts`、可选 `serviceTiers`，不返回选择或 default 字段。`/api/agent` 使用顶层 `modelKey/reasoningEffort/serviceTier`；NONE 表示关闭思考，未配置服务等级省略字段。详情不再返回 `model`、`selected*`、`modelConfig`、`modelOptions` 或 meta 中重复的模型信息，ACP 详情仅投影 meta.engineId；模型及其他会话选项由 prepare/config 返回，不保存在原生 modelKey。模型暂时不可用时前端保留配置并提示，不自动选其他模型。

Native 的 `models` 项仅消费 `key/name/icon/provider` 与可选 `serviceTiers`；不依赖 `modelId/protocol/isReasoner/isVision/contextWindow/timeout` 或模型级 `reasoningEfforts`。模型一致性诊断在没有 `modelId` 时使用 key/provider。ACP 模型不使用原生模型目录，选项来自真实 prepared 会话；Agent 编辑页仍从 `/api/admin/agents/editor-options` 读取模型级思考能力。顶层 `reasoningEfforts` 保持 `{key,label}` 对象数组，菜单优先使用客户端翻译，未命中时保留服务端 label（包括中文）。

`POST /api/agent/model-config` 只接受 `agentKey`（必填），以及至少一个 `modelKey/reasoningEffort/serviceTier`；省略设置保持原值，`serviceTier:null` 清除等级。响应为扁平 `{agentKey,modelKey,reasoningEffort,serviceTier?}`。不接受 key 别名和未知字段。选项缓存和手动刷新只更新能力列表。New Chat 的模型选择在保存成功后更新 Agent 默认配置；已有 Chat 的模型选择只更新该 Chat 的 Composer 偏好，不调用此接口。

`/api/agent.skills` 为 `{id,displayName}[]`，无技能时为空数组；管理编辑器转换为 id 数组写入 `definition.skillConfig.skills`，内部 YAML 结构不变。`meta.perAgentSkills` 已移除。

`interactionConfig` 是 `/api/agent` 返回的输入能力配置，不属于 `/api/query` 请求或 `request.query` 事件，也不从 Chat JSONL 的 `query` 恢复 Composer 能力。发送时仅提交用户实际选择的 `model`、`accessLevel`、`references` 等字段。Platform 在运行中冻结输入策略；重启恢复使用当前 Agent 定义重新准入；旧版 JSONL 中多出的 `query.interactionConfig` 是旧服务端写入，不能据此扩展公开 query 契约。


### Access level 的会话隔离

Composer 的 access level 由 `features/composer/lib/composerAccessLevel.ts` 管理：已有 Chat 按 chatId 保存；New Chat 按 agentKey 保存，各 Agent 的新会话偏好互不影响。加载已有 Chat 时，由 `features/runs/lib/accessLevel.ts` 读取当前活动根 Run 或最近一次根 Run 的服务端权限记录（Chat 详情 `activeRun.accessLevel/accessLevelVersion`、事件顶层的 `request.query.accessLevel` 与 `run.access_level.changed`，按版本取最新；运行中切换不写入历史，重新加载以 `activeRun` 为准）；活动 Run 同步实际档位，已完成 Chat 仅在没有本地偏好时初始化。缺少有效权限记录和本地偏好时使用 `ask_for_approval`，不继承当前 Agent 的 New Chat 偏好。切换 Chat 或 Agent 直接读取目标值，不复用组件本地权限状态。

通过 `chat_start`、Automation 或其他客户端创建的 Chat 也沿上述加载路径恢复权限。实时 query/start 和权限变更事件更新当前 Chat 的展示，按权限版本忽略重复及过时事件；其他 Chat、子任务、BTW 与解读事件不提供主对话权限。同步只投影服务端数据，不调用权限修改接口；当前后端未提供活动 Run 权限快照时，恢复使用已返回的事件记录。

首次 query 获得 canonical chatId 时，将发送时的实际 access level 初始化到该 Chat，包含附件上传预先分配 chatId 的情况；后续身份事件不覆盖已有选择。该 Chat 之后修改权限不回写 Agent 的 New Chat 偏好。运行中仍通过现有 `/api/access-level` 请求修改当前 Run，失败回滚绑定原 Chat，同一作用域的旧请求结果不覆盖新选择。Agent 能力关闭或详情尚未加载时，发送使用 `ask_for_approval`，不删除记住的偏好。

两份偏好通过前端 `sessionStorage` 保存，Platform 与 Gateway 均支持同窗口刷新恢复，按后端模式及身份分隔，浏览器同源存储提供站点隔离。Gateway 使用用户 subject，Desktop 使用宿主 auth context，独立 Platform 使用访问凭据指纹（凭据变化后使用独立偏好）。这不是服务端权限配置，不写入 `agent.yml`，不调用 Agent 配置更新接口，也不提供跨设备同步。


### 模型与思考强度的会话隔离

已有 Chat 的模型、reasoning effort 和 service tier 按 Chat 保存，New Chat 按 Agent 保存；切换会话直接读取目标值。加载旧 Chat 时优先保留该 Chat 的本地选择，否则从最近一次主 Run 的 request.query 事件顶层 `model` 恢复（不读取嵌套 `query`），并用同 Run 的 usage.snapshot 或详情用量快照补齐实际模型与思考强度；子任务、BTW、解读及其他 Chat 的事件不参与。记录未携带模型信息时只能显示当前 Agent 默认值，前端不猜测历史配置。

New Chat 选择仍保存到 Agent 默认配置，但不会覆盖已有 Chat 的选择或历史模型；已有 Chat 的调整作为下一次 query 的 model 发送，不写 Agent 配置。首个 query 取得 canonical chatId 时绑定发送时的模型，重复身份事件不覆盖之后的手工选择。模型能力暂未加载或被关闭时，不清除偏好，发送仍遵守 interactionConfig。

偏好使用 sessionStorage 按后端与身份隔离，支持同窗口刷新；尚未发送的调整不跨设备同步。保存 New Chat 默认值的异步响应绑定原目标，切换到旧 Chat 后不会把新值写入旧 Chat。


## Agent 默认权限与显式覆盖

Agent 的 `accessConfig.default` 由 Platform 解析，通过 `defaultAccessLevel` 展示。Composer 未明确选择时发送 `accessLevel: default`，由后台解析 Agent 默认；未配置回退 `ask_for_approval`。菜单只显示 Ask for approval、Auto-approve、Full access 三个具体档位，不显示默认/跟随选项，按钮按后台默认元数据或实际 Run 权限显示。用户明确选择后发送对应具体值；后续未明确选择的请求继续由后台决定，运行中不重新解析默认。服务端回传只进入观察状态，不变成用户选择。v3 偏好读取旧 v2 时把旧显式 default 解释为 ask_for_approval，保留用户原有选择。

权限偏好按身份和 Chat/Agent 隔离；v3 存储不恢复无法区分用户意图的旧 v1 值。Agent 管理表单可保存或清除默认权限；交互区重置只重置 interactionConfig。子 Agent 默认值可能高于父 Run，父 Run 降档不限制整条调用链。

ACP 外部项目复用 Composer、Terminal 与 HITL 容器。认证入口按 Platform 返回的类型和可用性展示；terminal helper 只能附着当前身份的认证操作。首次准备可预建 owned Chat，配置须经上游确认；发送前复核 revision，变化时停止发送并要求确认，切换 Chat 丢弃过期响应、取消未完成登录。外部许可沿用标准 approval 的 approve/reject 提交，原 optionId 只在 Platform 适配层映射；已完成或历史卡片只读。API key/device-code、持久许可和未验证能力保持关闭。真实双端登录/配置/首轮和 Windows 仍按 ACP-010/016 待实测。

认证取消后保留宿主已确认的认证方式列表，关闭原终端弹窗并允许原按钮重试；仍显示未认证且禁止发送，不把取消或会话准备成功当成凭据已通过。此行为复用原认证 UI，未增加网关 URL/Token 录入入口。


### 外部会话自动准备与切换

Composer 复用现有 Chat 加载及 Agent 可用性门禁。已有 Chat 在对话切换完成、Agent 可用后自动准备并读取当前会话配置，不依赖输入框聚焦、键盘或粘贴；加载中的过渡状态不提前准备，切换取消旧请求，迟到响应不能串会话。冷会话可能需要恢复上游 CLI，仍受宿主容量与回收策略约束。New Chat 预留本地 Chat ID，上传与首条 Query 共用该 ID，但打开新聊天不会执行真实 prepare：先 GET 配置预览，再 POST 后台刷新，Platform 合并探测并在 30 秒内去重。配置返回前仍可输入和发起发送，发送会等待真实准备；认证或配置异常时停止发送并显示原重试入口。StrictMode 和切换不另建草稿身份。

预览阶段 Mode/Model 选择保存在草稿，不发配置写入；刷新响应合并用户选择，不清空正文/附件。资源忙时保留菜单与输入能力，每 5 秒尝试刷新，切换或卸载停止定时器；认证失败仍提示登录，其余探测失败由显式重试/发送准备给出权威错误。发送前 Prepare 创建或恢复真实会话，逐项校验、Configure 应用选项，上游确认后才允许 Query；选项失效或被删除时中止，不静默回退。迟到的探测成功/失败不得覆盖发送准备后的结果。

切换到运行中的 Chat 不主动准备；若运行状态比请求晚到，engine_busy 不作为会话失败展示，轮次结束后刷新配置。准备接口明确返回 engine_busy 时，仅对相同 Chat 以 250/500/1000/2000ms 有界重试，最多五次请求；重试期间显示原准备状态。持续忙仍保留错误和重试入口，认证失败、网络错误、配置写入、登录、Query 和审批不自动重放。切换/卸载取消旧请求及重试定时器，迟到响应不覆盖当前 Chat。

回归测试同时覆盖真实 Composer 的加载门禁装配、空 chatId、运行状态晚到、短暂/持续忙、切换取消与 StrictMode。仅验证静态 ready 状态不足以覆盖此类时序缺陷；沿用现有 hook/组件测试，不引入额外状态框架。

### 本机 CLI 缺失提示（2026-11-06）

轻量 Adapter 不提供 CLI。dependency_missing 在原 EngineSessionNotice 中提示用户在引擎执行电脑安装并配置 CLI，继续使用原重试按钮，不增加安装/下载或网关配置入口。认证及会话准备仍走原接口。正式 Desktop 需要更新 Platform、插件和本 WebClient 后复验。

### ACP 切换与配置加载等待（2026-11-06）

历史 Chat 激活时先 GET 当前会话配置快照，驻留会话不再因导航申请 Prepare；仅明确 session_configuration_stale 才恢复准备，发送前和显式重试仍完整 Prepare，运行中只读规则不变。迟到结果不跨作用域应用。新对话沿用 GET 缓存/POST 刷新：无容量时最多两次延后重试（共三次请求），仍无缓存则结束转圈并展示原 engine_busy 重试入口；已有缓存保持菜单和发送可用，不增加 UI。

Platform 用真实 session/new 返回的默认选项填充原预览缓存，不使用其他 Chat 的手动选择或恢复结果。30 秒是后台刷新窗口，旧默认值在有界缓存中仍可先显示；实际发送重新校验。首次成功 Prompt 的 unknown→authenticated 仅确认既有凭据，不清空默认缓存；真正认证失效/登录仍失效。

自动化：Composer 57 套、642 项及类型/模块边界通过。正式 Desktop 与 standalone 的连续切换、冷启动及发送前配置复核待实测；已有会话快照快，不代表 Codex 冷会话创建快。

### ACP 派生对话（2026-11-09）

沿用每轮回答的派生按钮、`sourceChatId/sourceRunId` 请求和成功后导航；Native 行为保持。Platform 负责真实外部会话分叉与能力判断，客户端不复制凭据/上下文或指定外部 session ID。capability_unsupported 显示所选回答不支持派生，fork_point_unavailable 显示历史节点无法定位，engine_busy 复用忙碌提示；其他错误保留通用提示和调试记录。失败不导航、不自动重发派生请求。
