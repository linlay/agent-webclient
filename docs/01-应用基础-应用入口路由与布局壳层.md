# 应用入口路由与布局壳层

## 资源对话创建与修改

管理台保留手工创建、编辑和保存，同时提供独立的「通过对话创建／修改」入口，通过默认 Chat 智能体的新对话 URL 交接，仅使用 `newChat`、`composerSkill`、`composerDraft`。自动化选择 `platform-automation`；技能、Agent、连接器和注册配置选择 `platform-admin`。修改草稿包含资源名称与稳定标识，Registry 还包含分类，不携带配置正文或凭据。入口不发送消息、不预建资源；用户发送后由技能按现有工具权限执行并回读验证。

Desktop 将其当前默认 Chat Agent 作为管理页面的宿主上下文 `chatDefaultAgentKey` 提供；管理 guest 的 URL 导航在 Composer 消费前交接给 Main Chat。Standalone 没有 Desktop 默认偏好，按平台 nav 目录顺序选择第一个普通 Agent。缺少可用 Agent 显示错误，不能把被编辑对象作为承接 Agent。回到管理页重新读取最新资源。

ZIP 导入、下载、删除、授权与自动化启停/运行保留。Agent 和 Skill 创建弹窗支持直接创建与 ZIP 导入；Agent 表单与源码、Skill 文件与 Registry YAML 保持可编辑并可直接保存。自动化保留创建和编辑抽屉。切换到对话前确认丢弃未保存草稿。连接器内置包仍只读；Token 凭据配置继续在专用页面流程完成，不进入聊天草稿。Registry Tools 分类继续只读，不开放创建。


## 当前状态
`agent-webclient` 是单页 React 应用，入口由 `src/app/index.tsx` 挂载，`src/app/App.tsx` 负责装配路由、Ant Design 主题、应用状态上下文和全局运行时。`RealtimeTransportProvider` 位于 `AppProvider` 与主题、鉴权、Router 之间，按页面 guest 生命周期提供稳定 transport 实例。主对话体验按 Surface 拆分：根路由保留完整左右侧栏和 TerminalDock；Agent/Copilot 路由只保留各自允许的对话能力；Overview、Debug、Terminal 与 Project 可独立直达和刷新。

构建产物只包含主应用入口。公开 `/share/{shareId}` 由 Tunnel 直接返回完整静态 HTML，不进入本项目的 Router、`AppProvider`、鉴权边界或实时连接生命周期。

## 核心职责
- 建立根路由、独立管理页、独立 Run/Terminal Surface 和默认对话路由。
- 在应用顶层注入 `AppProvider`、主题、国际化和全局样式。
- 区分实时对话页面与独立管理页面，避免管理页误走实时传输模式。
- 承载全局 overlay、modal、dock、sidebar 等壳层 UI。

## 核心流程
浏览器加载 `public/index.html` 后进入 `src/app/index.tsx`，再由 `App.tsx` 根据当前 URL 渲染目标 Surface：

- `/`：完整网站，包含 LeftSidebar、RightSidebar 和 TerminalDock；只有该路由注册 Standalone WorkPanel 反向 action。
- `/agent/:agentKey`：主对话，不渲染 RightSidebar 或 TerminalDock；历史记录统一以 `chatId` query 进入。不存在 `/agent?agentKey=...` 兼容入口。
- `/copilot/:agentKey`：精简对话，不渲染 Debug Drawer、SidePanel、BTW、Preview、Planning 或 TerminalDock；不存在无 Agent 的 Copilot 页面。
- `/overview/:chatId`、`/debug/:chatId`：通过真实 `GET /api/chat` 构造页面局部 replay projection，不借用或改写当前主会话状态。Standalone 页面可根据 replay 返回的 active Run 局部订阅；Desktop WorkPanel 保持 replay-only，并在重新激活时刷新快照。
- `/source-viewer/:sourceId?chatId=...`、`/planning-viewer/:planningId?chatId=...`：读取同一 Chat 快照后按稳定 ID 定位，不订阅 live Run；Source 可通过 `chunkId` 指定初始 chunk。
- `/btw/:chatId?btwId=...`：先读取 Chat 解析 owner，再通过真实 `/api/btw` 运行页面局部多轮对话。刷新不恢复 BTW 历史，既有 `btwId` 只作为下一问的分支上下文，Standalone 不开放 Source 跳转。
- `/resource-viewer/:agentKey?chatId=...&file=...`：统一承载 Artifact 与 Reference 的 Resource Viewer 并读取 `/api/resource`；缺少可用 resource URL 时不生成独立路由。`/file-viewer/:agentKey?path=...` 只读取 Workspace `/api/file`，不加载 Chat。
- `/web-viewer?url=...` 是不带 Agent/Chat/Run 身份的全局 HTTP(S) 包装页；`/history` 是全局聊天历史页，支持按关键词、最后更新时间和 Agent/Team 归属筛选。可选 `agentKey` 只初始化一个可切换的 Agent 筛选；缺失或加载完成后无法匹配时使用 All。后续筛选只作用于页面本地结果，不改变路由或后端协议。
- `/terminal/:agentKey`：独立终端 Surface，`terminalKey` 缺省为 `main`。
- `/project/:agentKey`：独立 Project Surface；只有指定 Run 与 Diff 使用 `runId`，Diff 必须同时具备 `chatId + runId + path`。

`src/features/surfaces/surfaceRoutes.ts` 是上述路径的统一强类型注册、parser 与 builder。Overview、Debug、BTW 使用路径 `chatId`；Source、Planning 使用各自资源 ID；Resource、File、Project、Terminal、Agent 使用路径 `agentKey`。除 `/history?agentKey=...` 的初始筛选外，旧 `/artifact-view/:agentKey`、`/reference-view/:agentKey`、`/overview?view=...`、把 `agentKey` 用作 Agent 路由的 query 入口与 `history=1` 都不解析、不重定向，也不再输出。

对话壳层内的“历史对话”与独立 `/history` 必须保持两种语义：Copilot 顶栏、`/history` Composer 命令和全局快捷操作打开当前 Agent/Team 的页面内历史抽屉；只有显式访问独立 History Surface 才进入全局历史页。当前对象历史选择记录后在原对话壳层内加载，不创建新浏览器页面。

独立 `/history` 是 Standalone 页面；选择记录始终通过页面 Router 导航到对应 Agent Chat。Desktop 的主要 History 入口由宿主原生 dialog 和受限 Assistant bridge 实现，不嵌入该页面，也不由 WebClient 请求外层导航。

根 TerminalDock 与独立 Terminal Surface 共用 `TerminalWorkspace`，tab、持久化、会话关闭和 TerminalPane 生命周期只有一套实现。Standalone Overview/Debug 在 replay 给出匹配 active Run 时可只读订阅；Desktop Overview/Debug 始终作为 replay-only WorkPanel item，首次挂载执行 HTTP replay，宿主从 hidden 切回 active 时再 replay 一次，不轮询，也不申请 query/attach。

Router 内页面渲染异常和 Router 外应用装配异常都必须落到可见错误页，展示简短错误摘要、可展开技术详情以及重试/重载入口。渲染异常不能退化为空白页、无限 loading 或仅写入控制台。

## 边界与非目标
- 壳层只负责页面编排，不直接解释后端协议事件。
- 管理页路由只解析 URL 并装配 feature，不直接导入 `shared/data`；领域 hook 通过共享数据契约完成读写。
- 独立管理页与 Modal/Drawer 必须使用各自的布局 class，不得让弹窗的 `max-height` 约束作用到页面级控制台。
- 不在 layout 层堆业务状态归并逻辑；跨模块状态归并应进入 reducer、hooks 或对应 feature。
- `app/layout/LeftSidebar.tsx` 只注入 Command/Settings 动作，Worker 列表、会话预览和创建逻辑位于 `features/workers`；右栏目录只保留 `RightSidebar.tsx` 容器。
- Overview 顶部的“运行信息”由 `features/overview/components/OverviewRunInfo.tsx` 展示，主右栏与独立 Overview 共用 `lib/overviewRunInfo.ts` 的只读投影。任一产物、文件变化、计划或任务列表有内容时默认折叠，否则展开；用户手动操作后保持当前 Chat 的选择，切换 Chat 重新判断。折叠行保留状态与耗时，展开后显示执行者、实际模型与推理强度、上下文占用、开始/结束时间以及可复制的 Chat/Run ID。数据按 Chat/Run 匹配，不以 Composer 下一轮配置替代实际运行数据；缺失字段显示占位，缺少终态且无活跃 Run 时显示“状态待同步”。
- 主对话右侧栏继续由 `BtwProvider` 管理 BTW；独立 BTW 使用页面局部 projection，不读取或写入 sessionStorage。File、Resource、Web、History、Terminal、Project 不进入主对话 projection。

## 外观生命周期

App 在业务 Provider、RealtimeTransportProvider 与 Router 外稳定安装 AppearanceProvider；渲染错误边界位于外观层内部。明暗或皮肤变化不替换 Router、业务根节点或 transport。BaseShell 仅向外观控制器提供现有 URL 的临时明暗，AppState 从外观层投影最终明暗，不再落盘。主聊天 page/read surface 与 Copilot/WorkPanel 的 panel surface 分开，详见[皮肤与背景协作](82-界面基础-皮肤与背景协作.md)。

创建入口统一收敛为列表工具栏的 `+` 弹出菜单，菜单内选择「手工创建」或「通过对话创建」；连接器手工项为「导入 ZIP」。不额外展示对话创建按钮。回归需先点击 `+` 再分别选择两种方式，确认打开表单/导入弹窗或对话预填。

编辑入口采用「编辑自动化／智能体／技能／连接器／注册配置」弹出菜单，统一包含「直接编辑」和「通过对话编辑」。直接编辑打开原有表单或定位已有编辑区；保存保持独立。对话编辑遵循未保存草稿确认，不额外展示独立按钮。

技能页的编辑操作放在列表 item 的「更多」菜单中，提供「直接编辑」与「通过对话编辑」，针对被点击条目的 key 执行；详情区不保留单独编辑操作行。验证非当前选中技能的菜单不会编辑错对象。
