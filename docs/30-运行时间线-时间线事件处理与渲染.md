# 时间线事件处理与渲染

时间线消息容器、Markdown 代码块和嵌套链接会登记 Desktop 右键语义目标。消息与代码的右键复制处理器读取 React state/props 中的原始文本，不读取渲染后的 DOM；用户已有选区时由 Desktop Electron 上下文直接复制选区。嵌套目标按最近祖先优先，目标卸载时 WeakMap 登记随 ref cleanup 失效。

## 当前状态
Events 模块负责把 live/replay 协议事件转换为消息、content、reasoning、planning、tool、awaiting-answer、source 等投影命令；Conversation 模块应用命令；Timeline 模块只负责 view model 和组件渲染。

## 核心职责
- Events 根据 `event.type` 分派纯处理器并生成 `EventCommand`。
- Conversation 维护 node id 映射、文本增量、本地 cache，并提供 live/replay adapter。
- Timeline 渲染节点、debug panel 和 run transcript，不持有对话 session。
- 为右侧 debug panel 和 run transcript 提供可读输出。

## 核心流程
`useConversationEventHandler` 接收事件并调用 `processStreamEvent`。处理函数生成命令后由 `liveEventDispatch` 转为 App action，更新 timeline node map 和 order；历史回放则由 `conversationReplay` 应用同一批命令。渲染层按 node kind 选择对应 block。

### Tool 输出投影

`tool.output` 即使先于本地 tool node 到达，也会按 `toolId` 补建 running 节点。相邻同 stream segment 合并，重复或倒退的 `chunkIndex` 被忽略；单次调用最多保留 1 MiB UTF-8，超限后保留头尾并插入截断标记，以同时保住早期二维码和末尾错误。live cache、Chat 切换快照和 attach replay 会复制这份临时状态。

统一 `ToolPill` 在第一条非空过程输出到达时自动展开一次；用户随后手动折叠后，同一调用的后续 chunk 不再强制展开。运行期只显示过程内容，不重复显示 command、cwd、description 和 timeout 等工具参数；通用只读 xterm 直接融入时间线背景，无独立边框或底色。stdout / stderr 按 `chunkIndex` 已确定的顺序原样写入同一终端，不插入流标签或人工颜色；终端解释 LF、CR、退格、ANSI 和光标控制。过程终端优先加载 xterm WebGL renderer，以自定义 Block Element 铺满单倍行高的字符单元格，使二维码的相邻块行无额外空隙且模块接近正方形；WebGL 不可用或上下文丢失时回退到 xterm DOM renderer。终端按容器宽度排版，并随全部已保留缓冲内容增高而不设置内部纵向上限。运行中只复制原始过程输出，完成后复制参数加最终 result。收到 `tool.result` 后临时过程状态被清除，xterm 被销毁并由现有 result 区域替换，过程终端不可重新打开；没有 result 的异常终止会保留已收到的终端。

过程终端使用文本前缀识别纯追加更新，只把新后缀写入 xterm；Chat 切换、attach 恢复或 1 MiB 头尾截断导致保留文本不再是旧文本前缀时，终端会重置并重放当前保留内容。Native Host Bash 通过普通 pipe tee 发送原始控制流，因此 `\r`、退格和拆分到不同 chunk 的 ANSI 序列均由 xterm 连续解析；前端仍只模拟实际收到的 `tool.output`，最终以可能不同的 `tool.result` 为准。

默认 Debug 把 `tool.output` 当作 delta 事件隐藏，开启 `DELTA_LOGS_ENABLED` 后才逐条展示原始 chunk。它不参与 `tool.snapshot.arguments` 聚合。冷回放没有过程事件时只展示持久化 result。

## 阅读位置书签与恢复

`ConversationStage` 为 Main、Agent、Copilot 三个 Surface 分别维护内存阅读位置，键由当前身份作用域、`surfaceMode` 和 `chatId` 组成。书签存储是容量 150 的 LRU，不写浏览器持久化；Gateway 身份变化时全部清空，删除 Chat 时清理该 Chat 在所有 Surface 的记录。

时间线直接使用 `VirtualListItem.key` 作为 Virtuoso item key，并在 Item DOM 上写入稳定 key。滚动停止 150ms、Chat 切换前、页面隐藏和组件卸载时，记录首个实际可见条目的 key、原索引、前后邻居、相对 scroller 顶部偏移、粘底状态和可选 Virtuoso snapshot。恢复期间禁止回写书签。恢复完成标记只能在事务真正进入 `ready` 时写入；恢复 Effect 被依赖变化 cleanup 后，同一事务必须可重入。

书签包含两类安全签名：数据签名覆盖条目顺序、组成节点及会影响高度的内容与折叠状态；布局签名覆盖 Surface、容器宽度、主题和根字号。两者完全一致时才传入 snapshot，随后仍以语义锚点校正；否则按原锚点、后邻、前邻、合法化原索引的顺序回退。恢复滚动统一使用 `behavior: "auto"`，再通过 `scrollBy` 修正像素偏移；连续两帧误差不超过 1px 后立即完成。同一 `seq + targetChatId` 从首次进入恢复起使用不可重置的 2000ms 总期限，Effect cleanup 后以剩余时间重启；超时后以当前最佳位置进入 `ready` 并记录实际位置误差，不进入错误或重试流程。

历史加载、active run attach 和运行状态变化不会主动抢占阅读位置。骨架层只属于尚未确认 active run 的阻塞型历史加载、回放、恢复和错误事务；new Chat 原生 live query，以及 `/api/chat` 已确认带有效 `activeRun.runId` 的后台恢复事务，都直接显示 Timeline。后台恢复仍按 `applying → restoring → ready` 恢复书签，但不遮挡 Timeline 或锁定 Composer，且错误状态始终重新覆盖。只有处于底部且没有恢复中的 ready Chat、正在显示原生 live query 的 promotion Chat，或正在显示 active run 后台恢复的 Chat，才允许 `followOutput="smooth"`；用户本地发送 query 或点击回到底部按钮时，才通过显式 `conversationScrollRequest` 产生平滑到底部意图。无书签的普通历史 Chat 默认瞬时定位到底部。

## 边界与非目标
- Timeline 不发起 query、不处理对话 session，也不提交 HITL；它只展示投影后的状态。
- 事件字段兼容应收敛在 processor，不在每个展示组件重复读取原始事件。
- Debug 展示不代表协议规范，只是联调观察视图。
