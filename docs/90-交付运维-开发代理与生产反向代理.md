# 开发代理与 Desktop 托管

## 当前状态
本地开发由 Webpack Dev Server 代理 `/api/*`、`/ws` 和可选 `/api/voice/*`。正式发布只生成 Desktop Program Bundle，静态资源、runtime config 和代理由 Desktop main process 托管。公开分享文档及其内容寻址显示资源由 Tunnel 托管；HTML 模板不固定域名，Platform 使用当前 Tunnel origin 注入资源地址。

## 核心职责
- 本地开发时将 `/api/*`、`/auth/*` 和 `/ws` 转发到 `BASE_URL`。
- 设置 `VOICE_BASE_URL` 时追加语音 HTTP 和 `/api/voice/ws` 代理。
- 保持 Webpack HMR 使用 `/__webpack_hmr`，避免与业务 `/ws` 冲突。
- 公开分享 origin 的 `/share/*` 与 `/assets/conversation-export/*` 由边缘网关直接转发到 Tunnel，不经过 WebClient 开发代理或 Desktop Program Bundle。

## 核心流程
`make dev` 加载 `.env` 后启动 Webpack Dev Server。`make release` 生成带 manifest 的 Program Bundle，Desktop 同步该产物后在 main process 中提供静态托管、runtime config 和受控代理。浏览器始终访问同源业务路径，由当前托管层转发到对应上游。

## 边界与非目标
- 前端代理只负责转发，不修正后端协议语义。
- `VOICE_BASE_URL` 为空时语音代理和语音入口都应关闭。
- Program Bundle 不包含 Node.js 服务进程；不要把 dev server 行为写成 Desktop 运行时事实。
- WebClient bundle 和 runtime-config 均不得包含 Tunnel 内部地址或公开分享代理规则。
- WebClient 的唯一正式交付物是 Desktop Program Bundle。
