# 开发代理与 Desktop 托管

## 当前状态
本地开发由 Webpack Dev Server 代理 `/api/*`、`/ws` 和可选 `/api/voice/*`。正式发布只生成 Desktop Program Bundle，静态资源、runtime config 和代理由 Desktop main process 托管。公开分享文档及其内容寻址显示资源由 Tunnel 托管；HTML 模板不固定域名，Platform 使用当前 Tunnel origin 注入资源地址。

## 核心职责
- 本地开发时将 `/api/*`、`/auth/*` 和 `/ws` 转发到 `BASE_URL`。
- 设置 `VOICE_BASE_URL` 时追加语音 HTTP 和 `/api/voice/ws` 代理。
- 保持 Webpack HMR 使用 `/__webpack_hmr`，避免与业务 `/ws` 冲突。
- 公开分享 origin 的 `/share/*` 与 `/assets/conversation-export/*` 由边缘网关直接转发到 Tunnel，不经过 WebClient 开发代理或 Desktop Program Bundle。

## 核心流程
`make dev` 加载 `.env` 后启动 Webpack Dev Server。`make release` 生成带 manifest 的 Program Bundle，Desktop 同步该产物后在 main process 中提供静态托管、runtime config 和受控代理。浏览器始终访问同源业务路径，由当前托管层转发到对应上游。

## HTML 图表内置资源

WebClient 构建从已安装依赖输出浏览器单文件版本及许可证，开发服务和 Program Bundle 共享以下固定地址：

| 资源 | 当前版本 | 地址 |
|---|---|---|
| ECharts | 6.0.0 | `/assets/visualization/echarts.min.js` |
| Mermaid | 11.16.0 | `/assets/visualization/mermaid.min.js` |
| 可选页面样式 | WebClient 自有 | `/assets/visualization/preview.css` |
| 图表示例 | WebClient 自有 | `/assets/visualization/example.html` |

HTML 使用普通 `script src` 标签，分别调用全局对象 `echarts` 和 `mermaid`。两库没有必须另行加载的 CSS，也不依赖外部 CDN；可选页面样式与主应用样式隔离，不在主入口提前加载这些资源。依赖版本由 `package.json` 锁定。

HTML 文档预览及编辑器只在预览副本中将上述 JS/CSS 地址解析为当前 WebClient 的绝对地址，避免 Artifact 的 Platform URL 或 Blob base 将请求导向错误来源；源码保存内容不变。独立图表代码块继续使用既有 Webpack 依赖加载。该能力不包含 main-chat 的 HTML 自动内嵌，不向公开分享或下载后的本机 HTML 自动提供资源。

路径解析只保证声明的内置地址指向 WebClient，不拦截其他脚本 URL。Agent 提示词可以要求使用内置库，但这不是任意 HTML 的加载白名单或 CSP 强制策略。

## 边界与非目标
- Standalone 本机文件操作由 Webpack Dev Server 的 `/__webclient_local__/files` 中间件处理，独立于 Platform `/api/*` 与 Desktop 原生方案。仅接受 loopback 连接、localhost/loopback Host 与同源请求；POST 使用进程级随机令牌校验，只接受文件名和有界二进制内容，不接受任意路径或命令。
- 文件标签菜单显示“在 Finder 中显示”和“用默认应用打开”（按系统切换文件管理器名称）。前端先复用既有鉴权链路读取 Artifact、Reference 或 Workspace File，再将本地副本交给系统。副本位于操作系统临时目录中的私有 `agent-webclient-files-*` 目录，按原始内容和文件名复用，不覆盖用户对副本的编辑，也不自动写回后端。单文件上限 128 MiB，默认应用打开仅允许文档、媒体和压缩包扩展名，不执行脚本或程序。Linux 的文件管理器操作打开所在目录。
- 文件服务随 `make dev` 启动，新增或修改中间件后须重启服务；普通前端热更新不能重载 Node 中间件。远程浏览器或未启动本机服务时菜单保持可见并禁用，提示原因；Desktop 不显示这组 Standalone 操作。此中间件不进入 Program Bundle，也不增加生产托管链。
- 前端代理只负责转发，不修正后端协议语义。
- `VOICE_BASE_URL` 为空时语音代理和语音入口都应关闭。
- Program Bundle 不包含 Node.js 服务进程；不要把 dev server 行为写成 Desktop 运行时事实。
- WebClient bundle 和 runtime-config 均不得包含 Tunnel 内部地址或公开分享代理规则。
- WebClient 的唯一正式交付物是 Desktop Program Bundle。
