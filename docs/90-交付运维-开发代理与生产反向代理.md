# 开发代理与生产反向代理

## 当前状态
本地开发由 Webpack Dev Server 代理 `/api/*`、`/ws`、可选 `/api/voice/*` 和公开分享 API。容器部署由 Nginx 模板代理普通 API、主 WebSocket、可选语音服务及公开分享 API。Desktop Program Bundle 的 HTTP 托管由 Desktop main process 实现。

## 核心职责
- 本地开发时将 `/api/*`、`/auth/*` 和 `/ws` 转发到 `BASE_URL`。
- 设置 `VOICE_BASE_URL` 时追加语音 HTTP 和 `/api/voice/ws` 代理。
- 对 SSE 与 WebSocket 禁用代理缓冲，避免实时事件延迟。
- 生产 Nginx 的 `/api/` 请求体上限为 `34m`，可容纳 32 MiB 的 Skill ZIP 与 multipart 边界开销；后端仍负责最终大小与解压安全校验。
- 保持 Webpack HMR 使用 `/__webpack_hmr`，避免与业务 `/ws` 冲突。
- `/share/{shareId}` fallback 到 `/share/index.html`；`/api/public/shares/*` 使用部署侧 `SHARE_API_BASE_URL` 转发到 Tunnel，变量不写入浏览器运行时配置。

## 核心流程
`make dev` 加载 `.env` 后启动 Webpack Dev Server；生产容器启动时 `nginx-entrypoint.sh` 将 `BASE_URL`、可选 `VOICE_LOCATIONS` 和 `SHARE_LOCATIONS` 注入 Nginx 配置，并将 `BACKEND_MODE`、`SHARE_APP_DOWNLOAD_URL` 等写入运行时配置；浏览器始终访问同源路径，由托管层转发到对应上游。未设置 `SHARE_API_BASE_URL` 时公开分享 API 明确返回 503，不回退到 Agent Platform。

## 边界与非目标
- 前端代理只负责转发，不修正后端协议语义。
- `VOICE_BASE_URL` 为空时语音代理和语音入口都应关闭。
- Program Bundle 不包含 Node.js 服务进程；不要把 dev server 行为写成 Desktop 运行时事实。
- `SHARE_API_BASE_URL` 只属于托管层；前端 bundle、URL 和 runtime-config 均不得包含 Tunnel 内部地址。
