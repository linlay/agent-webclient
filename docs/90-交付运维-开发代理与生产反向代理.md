# 开发代理与生产反向代理

## 当前状态
本地开发由 Webpack Dev Server 代理 `/api/*`、`/ws` 和可选 `/api/voice/*`。容器部署由 Nginx 模板代理普通 API、主 WebSocket 与可选语音服务。公开分享文档及其内容寻址显示资源由 Tunnel 托管；HTML 模板不固定域名，Platform 使用当前 Tunnel origin 注入资源地址。Desktop Program Bundle 的 HTTP 托管由 Desktop main process 实现。

## 核心职责
- 本地开发时将 `/api/*`、`/auth/*` 和 `/ws` 转发到 `BASE_URL`。
- 设置 `VOICE_BASE_URL` 时追加语音 HTTP 和 `/api/voice/ws` 代理。
- 对 SSE 与 WebSocket 禁用代理缓冲，避免实时事件延迟。
- 生产 Nginx 的 `/api/` 请求体上限为 `34m`，可容纳 32 MiB 的 Skill ZIP 与 multipart 边界开销；后端仍负责最终大小与解压安全校验。
- 保持 Webpack HMR 使用 `/__webpack_hmr`，避免与业务 `/ws` 冲突。
- 公开分享 origin 的 `/share/*` 与 `/assets/conversation-export/*` 由边缘网关直接转发到 Tunnel，不经过 WebClient Nginx 或开发代理。

## 核心流程
`make dev` 加载 `.env` 后启动 Webpack Dev Server；生产容器启动时 `nginx-entrypoint.sh` 将 `BASE_URL` 和可选 `VOICE_LOCATIONS` 注入 Nginx 配置，并使用 `jq` 将 WebClient 自身运行时配置一次性安全序列化。浏览器始终访问同源业务路径，由托管层转发到对应上游。

## 边界与非目标
- 前端代理只负责转发，不修正后端协议语义。
- `VOICE_BASE_URL` 为空时语音代理和语音入口都应关闭。
- Program Bundle 不包含 Node.js 服务进程；不要把 dev server 行为写成 Desktop 运行时事实。
- WebClient bundle、Nginx 模板和 runtime-config 均不得包含 Tunnel 内部地址或公开分享代理规则。
