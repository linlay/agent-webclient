# 消息发送路由与运行控制

## 当前状态
消息发送由 `useComposerSend` 和 `useMessageActions` 协作完成。前者负责本地输入决策、slash 命令、steer 提交和 send event，后者监听 `agent:send-message` 并通过 `RunTransport` 创建 query session。steer 队列的增删、确认和草稿恢复由 Composer 的纯状态逻辑 `pendingSteers.ts` 维护，根 reducer 只负责组合。

## 核心职责
- 解析目标 chat、`RunOwner`、附件 references、运行参数和模型覆盖。
- 阻止同一对话重复并发发送，支持不同对话切换时 detach 当前 run。
- 在 streaming 状态下将普通输入转为 steer，支持已上传图片、HTML/MD 等普通文件以及混合附件，文字可为空。
- 管理 abort controller、requestId、runId、live session 和 timeline user message。

## 核心流程
用户触发发送后，`useComposerSend` 先处理 slash command 和 steer 场景，再派发 `agent:send-message`。`useMessageActions` 接收事件，解析 mention 和 preferred routing，创建 requestId，通过 `runs.startQuery` 启动 Platform stream，并将收到的事件交给 timeline handler。owner 优先级固定为已保存 chat、当前 run/session、再到新对话选择的 Agent 或 Team。Team 使用 `{ kind: "orchestrated-team", teamId }`，query 只发送 `teamId`；Team 内 `@成员` 保留在消息文本中交给协调器，不会改写 owner。只有原 query 不带 `chatId` 且归一化事件提供稳定 `chatId` 时，才通知 agent 路由把 `?newChat=` replace 为 `?chatId=`；失败、取消或没有稳定 ID 时不改变地址。

Main Chat 的“新对话重问”是一次有序路由事务，不是两个可独立派发的 UI event。Agent route 先生成一次性 13 位 `newChat` nonce；Desktop 环境等待宿主确认外层 route、guest URL 与无 owner Surface 已统一到该 nonce，Standalone 环境等待本地 route 提交。只有准备完成后才清空旧会话并发送一次无 `chatId` query。准备失败或超时保留来源 Chat 且不发送；稳定 `chatId` 到达后继续使用 replace 收敛同一临时路由。

steer 按 Chat 保存为 `queued`，点击引导后进入 `sending`。控制响应 `accepted:true` 只代表提交被接受，条目继续显示“等待确认”；匹配 `steerId` 的有效 `request.steer` 才确认移除，事件携带的 `chatId` / `runId` 也必须匹配。后台 query / attach 仍处理确认，历史加载也用回放事件校准漏掉的确认；同一 steer 的重复事件不重复创建时间线节点。

明确 `accepted:false` 时，将内容恢复到来源 Chat 的草稿，已有文字保留并在末尾追加。网络错误或缺少 `accepted` 的响应保留 `sending`，标记结果未确认，不自动重发；流已经确认后的迟到响应不再恢复草稿。运行结束只把尚未提交的首条 `queued` 转为普通消息；切换 Chat、切换 Run 或加载历史不触发这一自动发送。`sending` 在运行结束后仍保留，用户可以手动取消并恢复到草稿。

## 边界与非目标
- `RunOwner` 只在前端内部流转，API 不发送 `owner` 属性；序列化后 Agent 只带 `agentKey`，Team 只带 `teamId`。
- 已保存 Team chat 不会因成员 task event 的 `agentKey` 降级为 Agent chat。
- 不在发送流程中解释 tool、content、plan 等事件，这些由 events processor 负责。
- steer、interrupt、compact、remember、learn 等命令的协议字段以后端接口为准。

### 附件 steer

运行中粘贴图片继续调用 `/api/upload`，必须等待整组附件就绪；上传失败时保留附件并阻止发送。入队时冻结 `references` 并清空输入区，待发送条展示资源缩略图。提交 `/api/steer` 时携带引用；取消或明确拒绝恢复文字与附件到原 Chat，恢复的附件按 Chat 隔离并可单独删除。响应未知时保留发送状态，等待 `request.steer` 确认；Run 结束时有文字的 queued 项转 query 并携带引用和展示数据；纯附件 queued 项恢复到输入区，提示补充文字，禁止自动发起空文字 query。

实时与历史 steer 时间线均读取事件 `references` 展示附件，空文字附件事件也完成队列确认。query 的 `message` 始终必填（包括只有选中文字引用）；steer 要求文字、有效文件引用或含非空顶层 `text` 的选区引用至少一项。普通文件不要求视觉模型；图片在视觉模型中直接输入，非视觉模型接收文件引用，交由已配置的图片识别工具按需读取，不应因缺少原生视觉能力禁用发送。未支持的远端附件路径以服务端拒绝结果为准。`mustUseSkills` 仍不能用于活动 steer。后端需先更新到支持附件 steer 的版本，防止旧后端忽略新增字段。

划词引用弹层支持为每条原文编辑可选批注；清空后省略 `annotation`。主聊天、旁聊及独立旁聊共用编辑组件，发送后的时间线与待发送 steer 队列只读展示原文和批注。发送失败保留草稿。仅使用顶层 `text`，不读取 `meta.text`；服务端引用无需 name/sourceKind 即可回放。ID 保持原始值，由 Platform 在模型提示词中映射短编号。query 仍需输入消息文字，steer 可只提交有效划词引用。

划词编号使用独立正整数 `annotationIndex`，与 Reference ID 分离，进入请求及历史记录。页面蓝色序号气泡和模型称呼 `Annotation N` 均采用该值，不按文件/图片引用排序；编辑或清空批注不改变编号。当前页面创建划词时递增分配，接收其他窗口引用时避免与当前草稿编号冲突。DOM Range 仅在内存保留；添加引用后在原文附近打开无语音入口的可选批注栏，Enter 收起、Shift+Enter 换行，点击序号再次编辑。原文 DOM 消失或改变时隐藏锚点，引用仍可在片段汇总弹层编辑。
