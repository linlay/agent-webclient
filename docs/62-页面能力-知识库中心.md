# 知识库中心

左侧栏 Quick Actions 的知识库（KBases）按钮与 Agents 同级，点击在当前页面打开知识库对话框（最大宽度 1320px、高度 min(84dvh, 860px)，与 Agents 一致）；Copilot 使用同一命令容器的 Drawer，`/kbases` 仍可作为独立管理页访问；入口受 `QUICK_ACTIONS_ENABLED` 控制，设置菜单不再提供该入口。`app/pages/kbases` 只装配 `features/kbases`，该 feature 负责列表刷新、编辑表单、任务状态轮询和召回结果。接口定义与鉴权 HTTP 请求由 `shared/data` 提供。

支持新建、查看、名称描述编辑、collection 增删及名称/来源修改、删除、手动索引更新、已索引文档浏览和召回测试。创建和编辑均允许 1–32 个 collection，每项包含独立名称与 Platform 机器上的已有绝对源目录。名称与解析后的目录不能重复；移除 collection 或删除知识库都保留源目录。集合范围改变后，Platform 将库标记为 `unindexed` 并清零当前范围的 `indexedAt`，后台自动对账更新，避免展示旧范围的数据。仅修改名称描述或调整 collection 顺序保留索引。旧单目录库以 `workspace` collection 展示，已有索引和引用保持有效。首次索引由后台自动维护，“更新索引”用于手工触发。后台任务期间每两秒刷新定义列表，任务完成或失败后停止轮询。索引期间禁用编辑与删除；同一来源范围的更新失败后仍可查看已有成功索引的数据。

页面沿用 Agents / Skills 管理页的填充式搜索、同排刷新/新建按钮、平铺列表、可拖拽列表宽度和右侧固定工具栏。默认打开 Documents，Collection 是文档筛选维度，支持按集合和文件名/标题联合过滤，点击文档行的集合名也可筛选。选择集合后只显示该集合的单行源目录；不在顶部逐行展开所有来源。Retrieval test 为独立页签，其多选集合范围最多占一行。编辑窗口整体限高并滚动，保留集合数量、名称唯一性和字段校验。

召回默认使用 KBX `query` 综合召回，也可选择全文 `search`、向量相似度 `vsearch` 或图检索 `gsearch`。向量模式要求已配置查询模型且向量索引完整，图检索要求完整图谱；页面根据 `/status` 禁用未就绪方式并解释原因。`query` 使用可用通道，页面展示实际通道和不完整/降级提示。未选择集合时使用库的默认检索集合，也可显式选择多个集合，每条真实 chunk 单独展示 collection、集合内相对文件路径、片段编号、抽取文本行号和向量相似度，返回数量 1–50，结果保持 KBX 的统一相关性排序。文档列表也显示集合与路径。文档预览为前 200 行，截断时提示。切换知识库或卸载时取消未完成的数据请求，防止旧结果覆盖当前库。

模型默认来自 Platform runtime.kbx，可在 library.yml 覆盖 embedding 并配置 reranker、queryExpansion；页面不提供逐库模型编辑。中心已支持自动监听和 Native Agent 绑定，图谱构建和上传仍未接通。Platform 配置目录为 `AP_RUNTIME_DIR/kbases/<id>/library.yml`，索引保存在 `ru-kbases/<id>/`。创建请求使用 `{name,description,collections:[{name,sourcePath}]}`，召回请求使用 `{query,limit,collections?,method?}`，`method` 缺省为 `query`。定义响应包含配置修订值 `baseRevision`；编辑发送表单打开时的修订值，删除发送确认框打开时的修订值（查询参数），配置冲突由后端返回 409，页面保留编辑草稿并展示错误。状态响应先返回库生命周期与 `statsAvailable`，KBX 通道能力从可选的 `statistics.capabilities` 读取；首次索引前或统计不可用时不启用向量与图检索。

管理接口为 `/api/admin/kbases` 及 `/{id}`、`/{id}/refresh`、`/{id}/status`、`/{id}/files`、`/{id}/search`、`/{id}/read`，沿用 HTTP 鉴权与统一 JSON 包裹。

召回结果的 `score` 为原始查询与 chunk 的向量相似度，`scoreType: vector_similarity` 才显示数值（保留四位小数）；`score: null`、`scoreType: unavailable` 或旧后端缺少类型时显示 `—`，不使用排名分、全文分或图分作为替代。结果顺序保持后端融合排序；`rankingScore` 仅保留诊断用途，不作为界面相似度展示。相似度不是答案置信度，界面提示说明此区别。

管理列表中的 `invalidId: true` 条目只展示诊断，禁用编辑、刷新和删除，需在主机上修正目录名。`sourceWarnings` 与 `refreshError` 使用警告展示，与不可用状态的 `error` 分开；来源离线或刷新尚未开始即失败时，仍按 `indexedAt` 决定已完成索引是否可浏览。

集合支持 description，管理表单保留 include/exclude/chunk/defaultQuery。知识库配置不授予来源目录的文件读写权限，旧 editable 字段已删除；目录权限统一由 Agent Workspace、hostAccess 与通用 AccessPolicy 决定。editingMode 仅控制本次 Workspace 编辑，四种 Native Agent 显式 true/false 语义一致；省略时沿用模板默认值（KBASE 只读，其他可编辑）。

库级 retrieval（数量、候选预算、最低分、时效权重和可选模型开关）、查询模型与 collection.defaultQuery 由 YAML / 管理 API 配置。召回表单初始数量使用库 topK（缺省 8），用户修改后作为单次覆盖；集合未选择时遵循 defaultQuery（缺省 true），所有集合默认排除时返回空结果，显式选择仍可检索。defaultQuery 不影响文档浏览和编辑权限，编辑表单保存时保留该值；库级高级字段省略，由后端保留。重排与扩展只在相应查询触发，失败保留可用结果并报告降级，目标环境的延迟和检索质量待实测。

## 通用智能体在 Composer 选择知识库

Composer 的 ＋菜单复用 `features/kbases` 的选择器与按需加载 hook，支持搜索、多选、库状态与已选标签；前三项展开，更多项可展开或收起，每项可移除，也可清空。固定绑定库单独标注，固定绑定不会自动加入临时必用项。选择按 Chat 保留供下一轮使用，新 Chat 清空；未创建 Chat 的草稿按页面 Agent 隔离，接受首次 Query 后迁移到真实 Chat ID。冷回放仅在该 Chat 尚无用户选择记录时恢复最近主 Query，用户明确清空的选择不会被回放覆盖。

选择器不显示复选框，点击知识库条目切换选择后立即关闭整个 ＋菜单；重新打开可以继续添加其他库，已有选择保留。不可读条目与达到数量上限后的未选条目保持禁用。

Query 的顶层可选字段为 `mustUseKbases: string[]`，每项是知识库 ID；trim、忽略空 ID、按精确 ID 去重后最多 8 个，省略或空数组都表示本轮没有临时必用库。达到上限后选择器禁止添加未选项，已选项仍可移除；普通 Query、语音 Query 和 Automation 均检查规范化后的数量。它不属于 `params` 或 `references`，不定义 ACL，也不会自动挂载连接器或检索工具。后端的已解析 `interactionConfig.mustUseKbases` 始终返回 boolean；运行界面只在明确为 true 时启用入口，关闭开关时空选择仍可发送。Agent 编辑器允许配置这个开关。Automation 的结构化 Query 表单使用可选的库 ID JSON 数组，创建和修改同样归一化，复制与回显保留数组（包括显式空数组）。

前端使用端目录契约集中在 `src/shared/data/api/dto/kbases.ts` 的 `KBaseOptionsResponse`，接口是 `GET /api/kbases?agentKey=<实际目标 Agent>`，成功数据仍包在 `ApiResponse.data` 中。Platform 通过 routed client 使用主 WS，同路径与 HTTP 使用相同请求、响应；Gateway 使用 HTTP。目录不缓存、不调用管理 API，WS 失败不退回 HTTP。示例数据如下：

```json
{
  "agentKey": "general",
  "capability": {"available": true},
  "boundLibraryId": "fixed-library",
  "libraries": [{
    "id": "product-docs",
    "name": "产品文档",
    "description": "产品能力与发布记录",
    "collections": [{"name": "docs", "description": "使用说明"}],
    "readable": true,
    "indexing": true,
    "degraded": false
  }]
}
```

`capability.available`、`libraries[].readable/indexing/degraded` 是明确的后端判定，false 也必须返回；`libraries` 与 `collections` 为空时返回 `[]`。前端不从 Agent tools、索引状态或乐观默认值推断能力，不附加 search 工具组合门槛。`capability.reason` 可解释当前 Agent 不具备检索能力，单库 `unavailableReason` 可解释暂不可读；库说明和集合摘要均只读。`boundLibraryId` 可省略。目录不返回来源路径、管理配置、编辑权限、修订信息或其他完整管理 DTO。索引中但仍有可读旧索引的库允许选择，降级单独说明。选择后目录失效或库变得不可读时保留用户标签供检查／移除，Query 发起前重新读取目录；任一库不可用则整体拒绝，不静默删除无效项。

前导 `@Agent` 按既有 TEAM 成员路由解析实际目标，目录和发送校验均针对该目标。点击发送时把 ID 和展示标签复制到 `SubmissionDraft`；失败恢复不会覆盖用户随后修改的选择。主 Query 将字段送到 `RunTransport.startQuery` 与公共 `buildQueryPayload`；时间线的本地用户消息和 `request.query` 回放均保留 ID。观察者／attach 使用既有回放投影，detach 的对话快照保留节点元数据。重发、在新 Chat 重发使用原消息的库 ID 快照；原消息没有选库时不会借用当前输入框选择。规划批准调用 `/api/submit` 继续原 Run，不再发起 Query，也不修改原 Run 的库要求。

运行中的 Composer 发送沿用 steer，常驻知识库标签不会阻止该路径，也不会写入 `/api/steer`；更改选择供下一 Run 使用。排队 steer 在 Run 结束后转为后续 Query 时复制下一轮选择。语音的独立 Query 入口同样复制并核验选择。BTW 当前没有选库契约，存在选库时明确提示用户清空选择或使用主 Query，不静默丢失要求。

来源预览保留发布的 `libraryId` 和原始 `sourceId`，独立 Viewer URL 带可选 `libraryId`，查找可按库限定；chunk ID 仅在已选来源内部匹配。正文／下载继续使用 `/api/chat/sources/read`、`/api/chat/sources/file` 的既有 `{chatId,sourceId,...}` 契约，绝不转换为 Workspace 资源。Platform 的 sourceId 已包含库身份（例如 `kbase:<libraryId>/<collection>/<relativePath>`），后端必须继续保证不同库来源 ID 不冲突，即使相对文件名与 chunk ID 相同。

Platform 已在源码中实现本轮选库字段、使用端 HTTP/WS 目录、准入校验、模型提示词与 `request.query` 持久化，DTO 与本节一致。普通 Native Agent 默认启用输入开关，KBASE/TEAM/PROXY/CHANNEL 默认关闭；TEAM、ACP、PROXY、CHANNEL 不接受非空选择。`chat_start`、Automation query 和 `agent_invoke.tasks[]` 接收显式 `mustUseKbases`，子任务不继承父 Run 的选择；这些工具参数由前端沿用通用工具参数渲染。`kbase_list` 可发现全部库，四个检索工具都需要显式 `libraryId`；规划批准／attach 沿用原 Run 的选择。本地 fixture `qa/kbase-composer-preview.tsx` 验证真实前端组件与请求快照，前端解析／路由测试验证目录契约；后端自动化测试验证 HTTP/WS 与 Run 传播。当前运行的旧后端进程尚未由本任务更新，这些结果不等同于部署新版后的真实 UI 联调。

真实联调验收：未固定绑定的 GENERAL Agent 已挂载检索连接器时分别选择一库、多库及空选择；不可读库不能启动 Query；能力关闭或接口缺失有明确不可用状态；发送失败保留后续编辑；切换 Chat／新 Chat／TEAM 前导成员路由没有串选；历史回放、两种重发、规划批准、语音 Query、steer 和跨库同名来源保持各自快照。部署新版后端并完成登录态界面联调前，不宣称端到端通过。
