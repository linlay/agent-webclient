# 知识库中心

设置菜单 KBases Center 打开 `/kbases` 独立管理页。`app/pages/kbases` 只装配 `features/kbases`，该 feature 负责列表刷新、编辑表单、任务状态轮询和召回结果。接口定义与鉴权 HTTP 请求由 `shared/data` 提供。

支持新建、查看、名称描述编辑、删除、手动索引更新、已索引文档浏览和召回测试。创建时可添加 1–32 个 collection，每项包含独立名称与 Platform 机器上的已有绝对源目录。名称与解析后的目录不能重复，创建后集合及源路径固定；删除保留所有源目录。旧单目录库以 `workspace` collection 展示，已有索引和引用保持有效。首次索引需要点击“更新索引”。后台任务期间每两秒刷新定义列表，任务完成或失败后停止轮询。页面展示最近成功索引时间与错误；失败后仍可查看已有成功索引的数据。

召回默认使用 KBX `query` 综合召回，也可选择全文 `search`、向量相似度 `vsearch` 或图检索 `gsearch`。向量模式要求已配置查询模型且向量索引完整，图检索要求完整图谱；页面根据 `/status` 禁用未就绪方式并解释原因。`query` 使用可用通道，页面展示实际通道和不完整/降级提示。支持查询全部集合或选择多个集合，每条真实 chunk 单独展示 collection、集合内相对文件路径、片段编号、抽取文本行号和相关性分数，返回数量 1–50，结果保持 KBX 的统一相关性排序。文档列表也显示集合与路径。文档预览为前 200 行，截断时提示。切换知识库或卸载时取消未完成的数据请求，防止旧结果覆盖当前库。

模型来源为 Platform 的全局 KBX 配置，页面不提供逐库模型配置。当前中心未接通图谱构建、上传、自动监听或 Agent 挂载，不将图查询入口宣称为已交付图谱构建闭环。Platform 持久化目录为 `AP_RUNTIME_DIR/kbases-center`。创建请求使用 `{name,description,collections:[{name,sourcePath}]}`，召回请求使用 `{query,limit,collections?,method?}`，`method` 缺省为 `query`。管理接口为 `/api/admin/kbases` 及 `/{id}`、`/{id}/refresh`、`/{id}/status`、`/{id}/files`、`/{id}/search`、`/{id}/read`，沿用 HTTP 鉴权与统一 JSON 包裹。
