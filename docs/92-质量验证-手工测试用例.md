# 手工测试用例

## 当前状态
本项目以 Jest 单元测试为主，核心联调依赖外部 AGENT API、语音服务、Desktop 宿主和浏览器能力。手工测试用于覆盖代理、实时流、HITL、附件、Viewport、语音和发布包结构等跨系统场景。

## 核心职责
- 给出本地开发、容器部署和 release 包的最小检查路径。
- 覆盖 SSE/WS、attach、submit、steer、interrupt 等运行控制。
- 覆盖附件上传、artifact resource、viewport iframe、HITL 四种 mode。
- 明确哪些失败应回到后端协议或部署配置排查。

## 核心流程
先准备 `.env`，显式设置 `DESKTOP_APP=false` 并启动 `make dev` 或容器。确认页面可打开、agents/chats 通过 HTTP 加载，再执行一次普通 query、一次运行中 steer、一次 interrupt、一次带附件 query。随后用后端可触发的样例验证 artifact.publish、viewport block、frontend tool、question、approval、form、plan awaiting 和 voice。

## 双环境与独立 Surface 回归

1. Standalone 打开 `/`，确认左右侧栏和 TerminalDock 均存在；agents/chats/project/resource 请求走 HTTP，Run/Push/Terminal 共用一条 `/ws`。
2. 分别在 `DESKTOP_APP=false` 与 Frame Port Desktop 环境打开 `/agent/:agentKey`。Desktop 中 Overview/Debug 使用同一 Chat guest 的右侧次级视图；Planning、Artifact 和 File Diff 仍使用 WorkPanel OpenTarget。打开 `/copilot/:agentKey`，确认 BTW 与 Terminal 不可用。
3. 直接刷新 `/overview?lang=...&theme=...&chatId=...&runId=...&agentKey=...`、`/debug?...`、`/terminal?agentKey=...&terminalKey=main`、`/project`。Desktop Overview/Debug 只 HTTP replay，不发送 query、attach 或 detach；Standalone 在权威 active Run 匹配时可只读 subscribe。缺少 chatId 时显示稳定错误。
4. 根页面 Debug Panel 的 `chat.start` 行应提供 Agent、Copilot、Overview、Debug、Terminal 入口；事件或对应 chat 含合法 `shareId` 时再提供 `/share/{shareId}` 入口。不得用普通 `chatId` 拼接公开分享 URL。
5. Standalone Terminal 覆盖 open/status/write/resize；关闭 Surface 或切换 route 只 detach，关闭 tab 才 close。Desktop `/terminal` 显示 Frame Port unsupported，网络面板不得出现 guest `/ws`。
6. 连续切换 50 次路由，listener 回到基线；长流观察 pending/observer/timer 不持续增长；StrictMode 不产生重复 inbound/push 注册。
7. 设置 `DESKTOP_APP=true`：Frame Port 缺失时看到 `DESKTOP_BRIDGE_UNAVAILABLE`，transport version 错误时看到 `DESKTOP_BRIDGE_INCOMPATIBLE`。新聊天 query 不含预造 runId，只有关联 stream identity 后 URL 才获得稳定 chatId；`chat.created` 只更新列表。guest `/ws` 为 0，Main 保持单物理 Platform WS。

8. 从 Agent/Copilot/Kanban Chat 内切换 Chat/Overview/Debug，确认保持同一 `RunExecution` 且不产生 transport frame。Web、Planning、Artifact、File Diff 使用 canonical WorkPanel descriptor；缺少身份或无法安全转换 project-relative path 时不打开。

9. Platform 连续发送 N 条 delta，原生 WebSocket 和 Desktop socket factory 都投影 N 个同序 event。切换 Main/Copilot/Kanban 时只 detach 一次，detach frame 先于新 query/attach；返回后从 lastSeq attach。四类本地拒绝和 Platform 4xx 均生成等价 `ApiError`。

Desktop 宿主回归时，确认 guest storage、URL 和 DevTools 都不出现 access token，`GET /api/agent` 由 Main host 自动注入 token，并在一次 401 后刷新；401 页面显示重新登录提示，网络异常显示网络提示。`/ws` 的 HTTP/Upgrade 以及 query、attach、submit、interrupt、steer、access-level HTTP 请求均应被 host 固定拒绝且不触达 Platform。用 Desktop 的 New Chat 发送首条消息后，应从 `?newChat=` replace 为稳定 `?chatId=`，并由 Desktop 外层路由选中该对话；query 失败、取消或没有稳定 ID 时不得改变当前选中项。

发布验收必须先校验 Frame Port contract hash，再渲染 Program manifest 并确认无 `/auth`、`/ws`、SSE 特例，且 `/api` 为带 `agent-platform-access-token` 的 HTTP-only route。Frame Port Desktop、匹配 WebClient 和旧任一侧混用都必须明确阻断；Standalone `localhost:11948` 仍保留自己的 `/ws`。

Desktop 右键回归覆盖用户/助手消息、代码、Web 链接、Workspace 文件、Markdown 资源与 AttachmentCard：无选区复制所属原文，有选区只复制选区；链接复用右侧 Web Preview，文件复用 Workspace Preview，资源复用鉴权预览/下载。流式更新、虚拟列表卸载和坐标漂移后执行旧命令必须无操作。抓取 resolve 响应确认不含正文、代码、路径、Token、Bearer、资源临时 URL 或菜单文案。普通浏览器右键事件不得被取消。

## 公开对话分享回归

1. 通过公开边缘网关直接打开 Tunnel 返回的 `/share/share_xxx`，Network 中应只有主文档和 `/assets/conversation-export/<hash>/` 下的显示资源，不加载 WebClient 主应用 bundle、不建立 `/ws`，也不初始化 Token Bridge。
2. 正常响应必须是 `text/html; charset=utf-8`，正文与 Platform 上传字节一致，并包含 `no-store`、`nosniff`、`noindex` 和 `no-referrer` 响应头。
3. 使用包含中文、GFM、KaTeX、代码、ECharts、Mermaid 和原始 HTML 的完整文档验证正文、复制、折叠思考和图表降级；危险内容仍由导出模板的集中净化边界约束。
4. 撤销、到期、随机合法 ID 和非法 ID 均返回同一最小 404 HTML，不加载远程资源；页面不显示“打开 App”或下载客户端 CTA。
5. 执行生产构建并检查产物清单，确认没有 `share/` HTML、JS 或 CSS 入口，且 WebClient 代理配置不处理 `/share/*`。

## 静态 HTML 导出回归

1. 分别从 Chat Actions 和 History Modal 执行“导出静态 HTML”，确认浏览器只请求 Platform `format=html` 并直接下载完整响应；原 Markdown 导出入口保持独立。Desktop 也只读取 Platform 完整 HTML，不读取 WebClient 模板。
2. 用 `file://` 打开单个文件，联网时验证中文、GFM、KaTeX、固定语言高亮、折叠思考、深浅色、窄屏和打印。分别验证 `run.start` 比 query 早 1ms 与晚 1ms 都能展示；后续 reasoning/content/终态倒序仍显示安全错误。ECharts JSON 与 Mermaid 正常渲染，未知语言按源码显示，图片只显示省略提示。
3. 用包含 `</script>`、`<`、`&`、U+2028/U+2029、原始 HTML、事件属性、`javascript:`、`file:`、本地路径和异常 UTF-8 的 Snapshot 验证：JSON 直接存在于唯一 `application/json` script 且经过 HTML escaping，不使用 Base64；危险内容不执行，协议失败只显示安全错误。
4. 查看网络面板，初始页面只请求当前配置的 Tunnel origin 下、同一内容哈希目录内的 `runtime.css` 与 `runtime.js`；本地可为 loopback HTTP，生产必须为 HTTPS。KaTeX 字体相对该 CSS 加载，实际命中图表代码块时再各加载一次 ECharts/Mermaid。页面不得请求 Platform API、runtime-config、Desktop Bridge、WebSocket、EventSource、第三方 CDN 或正文图片。阻断图表资源时正文仍可读，图表区域回退源码和提示。
5. 验证 20 MiB Snapshot JSON、256 KiB 模板和 20 MiB 最终文件门禁，以及 Snapshot profile、asset-set hash 声明和唯一 marker 错误。模板失败不得回退远程地址或生成部分文件。
6. 执行 `npm run build`、`npm run sync:conversation-export` 与 `npm run check:conversation-export`，确认模板没有 `<style>`、没有内联可执行脚本、只有一个 Snapshot JSON marker；模板引用的 hash、SRI、manifest、Platform 模板和 Tunnel 资产字节必须一致，raw markup 只有统一 DOMPurify 边界。

Agent Copilot 从 `/copilot/zenmi?lang=zh&theme=light` 发送首条消息后，WebView URL 应原位增加稳定 `chatId` 并保留宿主参数，不得触发历史 reload 或第二个 query/attach。选择历史 chat 时 URL 与加载的 ID 同步且只加载一次；点击新对话时旧 `chatId` 立即清除，首条消息后再 replace 为新 ID；切换 Agent 时清除旧对话身份并保留语言、主题参数。

## Markdown 图片与 Artifact 资源回归

1. 直接生成一张图片，确认回答 Markdown 只使用 `filename`，页面以带鉴权 fetch 请求 `/api/resource?file=<chatId>/<filename>` 后显示；Markdown 和事件中不得出现真实 endpoint、`file://`、当前 chatId 前缀或 `chat_dir`。
2. 生成后再发布，确认 Artifact 卡片、右侧预览、下载链接与最终回答全部使用 `artifacts/runId/filename` 发布副本，不再使用生成源 URL。
3. 用中文、空格、`#`、`%` 文件名验证 query 双层编码正确，预览字节与 MIME 正确；刷新聊天与归档后回放仍可访问。
4. 回放一条历史 `/api/resource?file=...` Markdown，确认界面显示资源不可用且不发起 fetch。外部 HTTP(S)、`data:`、`blob:` 图片仍直接加载，不转换为本地资源。
5. 分别用 Bearer 和 Cookie 登录验证 ChatScope、普通 Agent Workspace 绝对路径与 `/tmp` 的图片、PDF、HTML、文本、音视频预览和下载；错误 chatId、跨用户、Workspace 外路径及 traversal 必须失败，Team Chat 的全部绝对路径必须在前后端都拒绝。

## 管理页面与弹窗布局回归

1. 在普通浏览器和 Desktop WebView 中分别打开 `/agents`、`/registries`、`/automations`、`/mcp-servers`，确认控制台从顶部铺满到底部，页面外层不出现空白或第二条滚动条；列表和详情区域各自滚动。
2. 在亮色、暗色以及宽度不超过 860px 的窗口重复检查，确认单列响应式布局仍占满可视高度。
3. 打开包含大量对话的 History Modal 和 Drawer，确认内容不超过 `70vh`，搜索工具栏保持可见，只有历史列表内部滚动。

## Skills 新建与 ZIP 导入回归

1. 打开 `/skills`，点击“新建技能”，确认弹窗默认进入“直接创建”，切换到“ZIP 包导入”后可拖放或选择一个 `.zip`，并从文件名自动填充可编辑的 Skill Key。
2. 直接创建有效 Key，确认弹窗关闭、列表新增并跳转到 `/skills/<key>`；空 Key、路径字符、`.example` 和现有 Key 必须在提交前阻止。
3. 分别导入根目录含 `SKILL.md` 和外包一层目录的 ZIP，确认成功后打开 `SKILL.md`；导入同名 Key 时弹窗保持打开并提示改名。
4. 导入非 ZIP、超过 32 MiB、缺少 `SKILL.md`、含 `../` 路径或无效 `.runtime-env.json` 的包，确认不生成技能目录，422 响应中的 `sourcePath/message` 显示在弹窗内。
5. 当前技能存在未保存文本时提交创建或导入，确认先出现放弃修改提示；取消提示后不得发送创建或导入请求。
6. 使用容器版页面重复一次接近 32 MiB 的 ZIP 导入，确认 Nginx 不返回 413，最终大小限制仍由后端统一响应。
7. 在技能文件树中选中图片文件（如 `assets/*.png`、`*.jpg`、`*.svg`），确认右侧显示图片预览，路径/大小/MIME/SHA-256 元信息仍然可见；选中视频或其他二进制文件不出现预览；切换文件或替换同路径图片后预览刷新；断网或文件被删除时显示失败文案且元信息网格保留。

## Skills 文件树操作回归

1. 选中技能后，文件树工具栏「新增文件」为弹出菜单：点击后出现「上传文件」和「新增文本文件」两项；「新增文本文件」弹出文件名输入框，并显示目标位置（根目录或当前目录），确认文件创建在锚点目录内。
2. 通过「上传文件」选择图片（png/jpg/gif/webp/svg 等），确认图片上传到当前锚点目录、文件树立即出现该项并自动选中；上传同名文件时后端应返回错误提示，不得静默覆盖。
3. 「新增目录」入口为弹出菜单，含「新建目录」与「新建子目录」两项：未选中任何项时「新建目录」在根目录创建，选中文件或目录时在其同级创建；「新建子目录」仅在选中目录时可用（未选中目录时为禁用态），在该目录内创建；创建后自动展开父目录并选中新目录。
4. 目录行主体点击后右侧显示目录信息视图（路径、子项数量与操作提示），目录可高亮选中；点击行内箭头可展开/收起，展开/收起不改变选中状态。
5. 选中目录后执行「新增文件」→ 上传或新增文本文件，确认文件创建在该目录内；「新增目录」弹窗的 placeholder 为「目录名称」（英文 Directory name），不得再出现「文件名（含扩展名）」（对应截图中的错误话术）。
6. 有未保存修改时在文件树切换选中（文件或目录），确认仍出现放弃修改确认；取消后选中不变化。
7. 对目录执行重命名/删除，确认整目录递归删除前有确认，删除后树与右侧视图同步刷新。

## Agent / Team 混合列表回归

1. 在 HTTP 与主 WebSocket 模式下分别刷新左侧栏，确认请求 `/api/agents` 都携带 `includeTeam=true`；HTTP query 与 WS payload 的 `includeChats`、`includeTeam`、`scope`、`mode` 字段一致。
2. 让上游返回交错的 Agent、Team 扁平项，其中 Team 带 `kind: "team"`、`stats` 和最近 `chats`。确认 Team 出现在左侧，最近对话可打开，未读数和总对话数优先使用 Team stats。
3. 为交错的 Agent、Team 提供不同 `updatedAt` 的最近 chat，确认默认“按时间”按最新 chat 的 `updatedAt` 倒序混排；相同时间按 `chatId` 稳定排序，无对话项保持后端混排回退顺序。切换“按名称”和新建 Agent 临时置顶仍按原交互工作。
4. 对 `scope`、`mode` 分别筛选 Agent，确认 Team 始终保留；Copilot scope 只剩 Team 时仍会按 Agent 空列表回退到 nav scope。
5. 请求 `/api/chats?mode=...`（以及 WS 对应调用），确认 Team-owned chat 没有被过滤，且从 Team 历史入口能够显示该对话。

## Agent / Team 混合列表回归

1. 在 HTTP 与主 WebSocket 模式下分别刷新左侧栏，确认请求 `/api/agents` 都携带 `includeTeam=true`；HTTP query 与 WS payload 的 `includeChats`、`includeTeam`、`scope`、`mode` 字段一致。
2. 让上游返回交错的 Agent、Team 扁平项，其中 Team 带 `kind: "team"`、`stats` 和最近 `chats`。确认 Team 出现在左侧，最近对话可打开，未读数和总对话数优先使用 Team stats。
3. 验证默认“按时间”顺序与上游按首条 `chats[0].lastRunId` 返回的混排顺序一致；切换“按名称”和新建 Agent 临时置顶仍按原交互工作。
4. 对 `scope`、`mode` 分别筛选 Agent，确认 Team 始终保留；Copilot scope 只剩 Team 时仍会按 Agent 空列表回退到 nav scope。
5. 请求 `/api/chats?mode=...`（以及 WS 对应调用），确认 Team-owned chat 没有被过滤，且从 Team 历史入口能够显示该对话。

## Side question 回归

1. 进入已有 chat，确认初始不显示 Side question Tab；执行 `/btw` 后应出现空白 Tab 并自动激活。执行 `/btw 问题` 时，首次 `/api/btw` 请求不得携带旧 `btwId`。
2. BTW idle 时确认 Composer 显示 Send；发送后必须立即切为危险态 Stop。runId/agentKey 尚未注册时 Stop 禁用，注册后启用；点击后在响应返回前显示 loading 且不能重复提交。
3. 分别在 SSE 与全局 WS 主对话模式下点击 BTW Stop，网络面板都应只出现 HTTP `POST /api/interrupt`。返回 `accepted: true` 时 BTW SSE 被本地终止并转 idle；返回 unmatched、其他 rejected 响应或模拟网络错误时仍保持 running、继续接收内容并允许再次点击 Stop。
4. BTW 回答中关闭 Tab，确认没有发送 `/api/interrupt`、当前 SSE 没有被前端 abort，Tab 立即消失并回到 Overview。等待旧流继续返回 identity、事件和 terminal 后，Tab 不得复活；再次 `/btw` 必须是空 transcript、无旧 `btwId` 的新分支，旧流不得写入新分支。
5. 刷新页面前保留一个 running BTW，刷新后确认只对持久化恢复的 run 调用一次 `/api/attach`；正常新发起的 `/api/btw` 不得并发 attach。attach not-found 不应覆盖 live run 状态或使 Stop 消失。
6. 在多个 chat 间分别创建 BTW，确认 Tab 与内容按 chat 隔离。桌面 Tab 关闭和 Copilot BTW 面板关闭都应丢弃对应 chat 的分支；右侧栏最外层关闭按钮只收起，再打开时原 BTW 仍在。

## 边界与非目标
- 手工测试不替代 `make test`。
- 没有可用后端时，只能验证静态页面、路由和构建，无法完成实时协议回归。
- 语音和 Desktop 桥接需要对应运行环境，普通浏览器失败不一定代表前端代码错误。
