# 手工测试用例

## 当前状态
本项目以 Jest 单元测试为主，核心联调依赖外部 AGENT API、语音服务、Desktop 宿主和浏览器能力。手工测试用于覆盖代理、实时流、HITL、附件、Viewport、语音和发布包结构等跨系统场景。

## 核心职责
- 给出本地开发、容器部署和 release 包的最小检查路径。
- 覆盖 SSE/WS、attach、submit、steer、interrupt 等运行控制。
- 覆盖附件上传、artifact resource、viewport iframe、HITL 四种 mode。
- 明确哪些失败应回到后端协议或部署配置排查。

## 核心流程
先准备 `.env`，显式设置 `DESKTOP_APP=false` 并启动 `make dev` 或容器。确认页面可打开、agents/chats 按当前 backend 能力表通过主 WebSocket 加载，再执行一次普通 query、一次运行中 steer、一次 interrupt、一次带附件 query。随后用后端可触发的样例验证 artifact.publish、viewport block、frontend tool、question、approval、form、plan awaiting 和 voice。

## 双环境与独立 Surface 回归

1. Standalone 打开 `/`，确认左右侧栏和 TerminalDock 均存在；Platform 下 agents/chats 与 Run/Push/Terminal 共用一条 `/ws`，project/resource 继续走 HTTP。
2. 分别在 `DESKTOP_APP=false` 与 Frame Port Desktop 环境打开 `/agent/:agentKey`。Desktop Agent TopNav 右侧快捷组为空，Desktop 外层仅在 Main Chat 提供 WorkPanel 按钮；管理页、Copilot、Website/WebApp 不出现该入口。Standalone Agent/root 原有按钮保持不变。打开 `/copilot/:agentKey`，确认 BTW 与 Terminal 不可用。
3. 在 `DESKTOP_APP=false` 的根页面创建稳定 Chat 后，通过 Platform 触发七个 `desktop.workpanel.*`：确认内置项 ID 为 `sidebar:*`、网页项 ID 稳定为 `web:<base64url>`，refresh 会激活目标，closeWorkpanel 隐藏但不删除网页；错误 Chat、native、其他 module、固定/不可关闭网页均拒绝。再在 `DESKTOP_APP=true` 确认 guest 未注册 `desktop.action.call` provider。
4. 直接刷新 `/overview/:chatId`、`/debug/:chatId`、`/planning-viewer/:planningId?chatId=...`、`/source-viewer/:sourceId?chatId=...&chunkId=...`、`/resource-viewer/:agentKey?chatId=...&file=...`、`/file-viewer/:agentKey?path=...&line=...`、`/terminal/:agentKey?terminalKey=main` 与 `/project/:agentKey`。缺少或错误稳定 ID 必须显示无效目标；File 不请求 Chat。旧 `/artifact-view/:agentKey`、`/reference-view/:agentKey`、query `agentKey`、`history=1`、`/overview?view=...` 均不得解析、重定向或输出。
5. 根页面 Debug Panel 的 `chat.start` 行应提供 Agent、Copilot、Overview、Debug、Terminal 入口；事件或对应 chat 含合法 `shareId` 时再提供 `/share/{shareId}` 入口。不得用普通 `chatId` 拼接公开分享 URL。
6. Standalone Terminal 覆盖 open/status/write/resize；关闭 Surface 或切换 route 只 detach，关闭 tab 才 close。Desktop `/terminal` 显示 Frame Port unsupported，网络面板不得出现 guest `/ws`。
7. 连续切换 50 次路由，listener 回到基线；长流观察 pending/observer/timer 不持续增长；StrictMode 不产生重复 inbound/push 注册。
8. 设置 `DESKTOP_APP=true`：Frame Port 缺失时看到 `DESKTOP_BRIDGE_UNAVAILABLE`，transport version 错误时看到 `DESKTOP_BRIDGE_INCOMPATIBLE`。新聊天 query 不含预造 runId，只有关联 stream identity 后 URL 才获得稳定 chatId；`chat.created` 只更新列表。guest `/ws` 为 0，Main 保持单物理 Platform WS。

9. 从 Main Chat 打开 Overview、Debug、BTW、Source、Planning、Artifact、Reference、File 与 File Diff，确认使用各自判别式 context 和 canonical WorkPanel descriptor；Artifact/Reference 的 `module` 与 context 保持各自契约，但 route 都落到 Resource。Desktop 缺少 `currentWorker.workspaceDir` 时点击 POSIX、Windows 或 UNC File 路径仍立即创建 File WorkPanel；请求 `/etc/hosts` 时面板先打开，再明确展示 Platform 403，不得静默写入 debugLines。除 Project 指定 Run/Diff 外 descriptor/URL 不含 `runId`。Web item 继续直接承载目标 HTTP(S) URL，Standalone Web 则使用全局 `/web-viewer` 且不含 Agent/Chat/Run。Overview/Debug 在 Desktop 中不 attach，隐藏后重新激活时刷新 `/api/chat`；跨 Chat projection 隔离正确。

10. Platform 连续发送 N 条 delta，原生 WebSocket 和 Desktop socket factory 都投影 N 个同序 event。切换 Main/Copilot/Kanban 时只 detach 一次，detach frame 先于新 query/attach；返回后从 lastSeq attach。四类本地拒绝和 Platform 4xx 均生成等价 `ApiError`。

11. 注入一个 Router 内组件渲染异常和一个 Router 外应用装配异常，均应显示 WebClient 错误页、错误摘要、技术详情与恢复按钮；不得出现空白页、无限 loading 或只有控制台错误。

Desktop 宿主回归时，确认 guest storage、URL 和 DevTools 都不出现 access token。服务冷启动直接进入 `/agent/:agentKey` 时，首个数据请求允许为 WS `/api/agent`，不依赖 `/api/agents` 预热，页面不得出现 `Failed to load agent`，且 Inspector 中只有一个有效 logical socket；`/api/agents`、`/api/agent` 与后续 `/api/chat` 均通过 Main Broker 的 Platform Socket request/response frame 完成。人为延迟 surface 登记时应在 Desktop 规定窗口内恢复；永久缺失时不得转发到 Platform。注入握手前 `1008 + surface_unavailable` 等带 reason 的 close，错误/debug 信息应包含 reason 而不是缺少 access token；显式 Retry 可重新请求，且不得自动重试或回退 HTTP。真正要求 token 的 Standalone Platform 模式在 token 为空时仍显示缺少凭据。WS 401 页面显示重新登录提示，网络异常显示网络提示且不得回退 HTTP。`/ws` 的 HTTP/Upgrade 以及 query、attach、submit、interrupt、steer、access-level HTTP 请求均应被 host 固定拒绝且不触达 Platform。用 Desktop 的 New Chat 发送首条消息后，应从 `?newChat=` replace 为稳定 `?chatId=`，并由 Desktop 外层路由选中该对话；query 失败、取消或没有稳定 ID 时不得改变当前选中项。

发布验收必须先校验 Frame Port contract hash，再渲染 Program manifest 并确认无 `/auth`、`/ws`、SSE 特例，且 `/api` 为带 `agent-platform-access-token` 的 HTTP-only route。Frame Port Desktop、匹配 WebClient 和旧任一侧混用都必须明确阻断；Standalone `localhost:11948` 仍保留自己的 `/ws`。

Desktop 右键回归覆盖用户/助手消息、代码、Web 链接、Workspace 文件、Markdown 资源与 AttachmentCard：无选区复制所属原文，有选区只复制选区；链接复用右侧 Web Preview，文件复用 Workspace Preview，资源复用鉴权预览/下载。流式更新、虚拟列表卸载和坐标漂移后执行旧命令必须无操作。抓取 resolve 响应确认不含正文、代码、路径、Token、Bearer、资源临时 URL 或菜单文案。普通浏览器右键事件不得被取消。

## 公开对话分享回归

1. 设置 `SHARE_API_BASE_URL` 指向 Tunnel，直接打开 `/share/share_xxx` 并刷新，确认始终命中 `/share/index.html`，脚本和样式从 `/share/` 加载。
2. 确认页面只请求同源 `/api/public/shares/share_xxx`，请求不携带 Cookie、Bearer 或 Desktop Token，且不会建立 `/ws`、SSE 或 Token Bridge。
3. 正常快照按 `entries` 混合 user、多个 reasoning 与 assistant；确认每轮回复聚合为一个默认折叠入口，提供重复的 `durationMs=174000` 时只显示一次“已完成 2m54s”。打开外层后，最后一条 assistant 内容之前的 reasoning snapshot 与 assistant 过程内容必须保持原始穿插顺序；每个 reasoning 以自身 `label` 或“思考过程”形成独立的第二层折叠，默认收起且互不影响，打开后显示淡色正文和引导线；仅最后一条 assistant 内容作为最终答复始终显示在外层。公开快照不接受或展示工具调用 entry。未提供 `durationMs` 时外层入口显示“已完成”。同时确认用户气泡右对齐、助手正文左对齐，顶部仅保留 AI 内容提示、不显示“更新于”。再验证 404/410、接口失败和非法 schema；确认显示稳定的只读状态，不跳转登录。
4. 使用含 GFM 表格、KaTeX、普通代码块、ECharts、Mermaid、原始 HTML、脚本 URL、图片和本地资源引用的内容验证：正文渲染与主对话一致，首次块级代码加载期间源码可见，加载后 AntD 折叠、复制、ECharts 和 Mermaid 能力完整；ECharts 只接受 JSON 对象，JavaScript 表达式和原始 HTML 不执行，危险链接不可点击，图片不发起外部或本地资源请求。
5. 在亮色、暗色、窄屏和无剪贴板权限环境验证 Header、展示及复制反馈；复制全文包含 reasoning，页面响应头包含 `X-Robots-Tag: noindex, nofollow, noarchive`。
6. 设置一个实际可访问的 HTTP(S) 客户端下载地址到 `SHARE_APP_DOWNLOAD_URL`，点击底部“打开 ZenMind”并确认浏览器发起 `zenmind://open`；页面保持可见约 1.5 秒后出现下载入口。非法或缺失 URL 时不显示下载入口，关闭悬浮条后当前页面不再展示。
7. 执行生产构建和 `npm run check:share-bundle`，确认全部分享 chunk 不包含 `src/app`、`src/features`、鉴权或 Desktop 数据模块，并仍包含共享 Markdown、reasoning disclosure、代码、ECharts 和 Mermaid 渲染器。

Agent Copilot 从 `/copilot/zenmi?lang=zh&theme=light` 发送首条消息后，WebView URL 应原位增加稳定 `chatId` 并保留宿主参数，不得触发历史 reload 或第二个 query/attach。选择历史 chat 时 URL 与加载的 ID 同步且只加载一次；点击新对话时旧 `chatId` 立即清除，首条消息后再 replace 为新 ID；切换 Agent 时清除旧对话身份并保留语言、主题参数。

## Side question 回归

1. 进入已有 chat，确认初始不显示 Side question Tab；执行 `/btw` 后应出现空白 Tab 并自动激活。执行 `/btw 问题` 时，首次 `/api/btw` 请求不得携带旧 `btwId`。
2. BTW idle 时确认 Composer 显示 Send；发送后必须立即切为危险态 Stop。runId/agentKey 尚未注册时 Stop 禁用，注册后启用；点击后在响应返回前显示 loading 且不能重复提交。
3. 分别在 SSE 与全局 WS 主对话模式下点击 BTW Stop，网络面板都应只出现 HTTP `POST /api/interrupt`。返回 `accepted: true` 时 BTW SSE 被本地终止并转 idle；返回 unmatched、其他 rejected 响应或模拟网络错误时仍保持 running、继续接收内容并允许再次点击 Stop。
4. BTW 回答中关闭 Tab，确认没有发送 `/api/interrupt`、当前 SSE 没有被前端 abort，Tab 立即消失并回到 Overview。等待旧流继续返回 identity、事件和 terminal 后，Tab 不得复活；再次 `/btw` 必须是空 transcript、无旧 `btwId` 的新分支，旧流不得写入新分支。
5. 刷新页面前保留一个 running BTW，刷新后确认只对持久化恢复的 run 调用一次 `/api/attach`；正常新发起的 `/api/btw` 不得并发 attach。attach not-found 不应覆盖 live run 状态或使 Stop 消失。
6. 在多个 chat 间分别创建 BTW，确认 Tab 与内容按 chat 隔离。桌面 Tab 关闭和 Copilot BTW 面板关闭都应丢弃对应 chat 的分支；右侧栏最外层关闭按钮只收起，再打开时原 BTW 仍在。
7. 独立打开 `/btw/:chatId`，先确认页面通过 `/api/chat` 解析 owner；首个 `/api/btw` 响应返回 `btwId` 后 URL 必须 replace 补全。后续多轮把该 `btwId` 作为分支上下文且可使用不同内部 runId，但 URL 不出现 runId；支持 Stop 与错误展示。刷新 `/btw/:chatId?btwId=...` 后 Timeline 必须为空，不读取 sessionStorage，下一问仍携带 URL 中的 `btwId`；Standalone BTW 不显示 Source 入口。

## 边界与非目标
- 手工测试不替代 `make test`。
- 没有可用后端时，只能验证静态页面、路由和构建，无法完成实时协议回归。
- 语音和 Desktop 桥接需要对应运行环境，普通浏览器失败不一定代表前端代码错误。
