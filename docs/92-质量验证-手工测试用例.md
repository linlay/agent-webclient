# 手工测试用例

## 当前状态
本项目以 Jest 单元测试为主，核心联调依赖外部 AGENT API、语音服务、Desktop 宿主和浏览器能力。手工测试用于覆盖代理、实时流、HITL、附件、Viewport、语音和发布包结构等跨系统场景。

## 核心职责
- 给出本地开发、容器部署和 release 包的最小检查路径。
- 覆盖 SSE/WS、attach、submit、steer、interrupt 等运行控制。
- 覆盖附件上传、artifact resource、viewport iframe、HITL 四种 mode。
- 明确哪些失败应回到后端协议或部署配置排查。

## 核心流程
先准备 `.env` 并启动 `make dev` 或容器。确认页面可打开、agents/chats 可加载，再执行一次普通 query、一次运行中 steer、一次 interrupt、一次带附件 query。随后用后端可触发的样例验证 artifact.publish、viewport block、frontend tool、question、approval、form、plan awaiting 和 voice。

Desktop 宿主回归时，还需确认 `desktop:agent-auth:response` 会先应用 `desktopAuthContext` 再写入 token；重启 `agent-platform` 后旧 token 不得被复用，页面能通过宿主 bridge 恢复 HTTP 与 WebSocket 请求。Desktop URL 中不应出现或传播 `desktopAuthContext`。用 Desktop 的 New Chat 发送首条消息后，应从 `?newChat=` replace 为稳定 `?chatId=`，并由 Desktop 外层路由选中该会话；query 失败、取消或没有稳定 ID 时不得改变当前选中项。

## Markdown 图片与 Artifact 资源回归

1. 直接生成一张图片，确认回答 Markdown 使用 `chatId/filename`，页面以带鉴权 fetch 请求 `/api/resource?file=...` 后显示；网络面板中不得请求 `file://`、`/Users/...`、Windows 绝对路径或 `chat_dir`。
2. 生成后再发布，确认 Artifact 卡片、右侧预览、下载链接与最终回答全部使用 `chatId/artifacts/runId/filename` 发布副本，不再使用生成源 URL。
3. 用中文、空格、`#`、`%` 文件名验证 query 双层编码正确，预览字节与 MIME 正确；刷新聊天与归档后回放仍可访问。
4. 回放一条历史 `/api/resource?file=...` Markdown，确认它原样 fetch、没有变成嵌套 `file=/api/resource?...`。外部 HTTP(S) 图片仍直接加载，不转换为本地资源。
5. 分别用 Bearer 和 Cookie 登录验证图片、PDF、HTML、文本、音视频的预览与下载；错误 chatId、跨用户资源及 traversal 返回失败时，界面不得尝试本机绝对路径兜底。

## 管理页面与弹窗布局回归

1. 在普通浏览器和 Desktop WebView 中分别打开 `/agents`、`/registries`、`/automations`、`/mcp-servers`，确认控制台从顶部铺满到底部，页面外层不出现空白或第二条滚动条；列表和详情区域各自滚动。
2. 在亮色、暗色以及宽度不超过 860px 的窗口重复检查，确认单列响应式布局仍占满可视高度。
3. 打开包含大量会话的 History Modal 和 Drawer，确认内容不超过 `70vh`，搜索工具栏保持可见，只有历史列表内部滚动。

## Skills 新建与 ZIP 导入回归

1. 打开 `/skills`，点击“新建技能”，确认弹窗默认进入“直接创建”，切换到“ZIP 包导入”后可拖放或选择一个 `.zip`，并从文件名自动填充可编辑的 Skill Key。
2. 直接创建有效 Key，确认弹窗关闭、列表新增并跳转到 `/skills/<key>`；空 Key、路径字符、`.example` 和现有 Key 必须在提交前阻止。
3. 分别导入根目录含 `SKILL.md` 和外包一层目录的 ZIP，确认成功后打开 `SKILL.md`；导入同名 Key 时弹窗保持打开并提示改名。
4. 导入非 ZIP、超过 32 MiB、缺少 `SKILL.md`、含 `../` 路径或无效 `.runtime-env.json` 的包，确认不生成技能目录，422 响应中的 `sourcePath/message` 显示在弹窗内。
5. 当前技能存在未保存文本时提交创建或导入，确认先出现放弃修改提示；取消提示后不得发送创建或导入请求。
6. 使用容器版页面重复一次接近 32 MiB 的 ZIP 导入，确认 Nginx 不返回 413，最终大小限制仍由后端统一响应。

## Agent / Team 混合列表回归

1. 在 HTTP 与主 WebSocket 模式下分别刷新左侧栏，确认请求 `/api/agents` 都携带 `includeTeam=true`；HTTP query 与 WS payload 的 `includeChats`、`includeTeam`、`scope`、`mode` 字段一致。
2. 让上游返回交错的 Agent、Team 扁平项，其中 Team 带 `kind: "team"`、`stats` 和最近 `chats`。确认 Team 出现在左侧，最近会话可打开，未读数和总会话数优先使用 Team stats。
3. 为交错的 Agent、Team 提供不同 `updatedAt` 的最近 chat，确认默认“按时间”按最新 chat 的 `updatedAt` 倒序混排；相同时间按 `chatId` 稳定排序，无会话项保持后端混排回退顺序。切换“按名称”和新建 Agent 临时置顶仍按原交互工作。
4. 对 `scope`、`mode` 分别筛选 Agent，确认 Team 始终保留；Copilot scope 只剩 Team 时仍会按 Agent 空列表回退到 nav scope。
5. 请求 `/api/chats?mode=...`（以及 WS 对应调用），确认 Team-owned chat 没有被过滤，且从 Team 历史入口能够显示该会话。

## Agent / Team 混合列表回归

1. 在 HTTP 与主 WebSocket 模式下分别刷新左侧栏，确认请求 `/api/agents` 都携带 `includeTeam=true`；HTTP query 与 WS payload 的 `includeChats`、`includeTeam`、`scope`、`mode` 字段一致。
2. 让上游返回交错的 Agent、Team 扁平项，其中 Team 带 `kind: "team"`、`stats` 和最近 `chats`。确认 Team 出现在左侧，最近会话可打开，未读数和总会话数优先使用 Team stats。
3. 验证默认“按时间”顺序与上游按首条 `chats[0].lastRunId` 返回的混排顺序一致；切换“按名称”和新建 Agent 临时置顶仍按原交互工作。
4. 对 `scope`、`mode` 分别筛选 Agent，确认 Team 始终保留；Copilot scope 只剩 Team 时仍会按 Agent 空列表回退到 nav scope。
5. 请求 `/api/chats?mode=...`（以及 WS 对应调用），确认 Team-owned chat 没有被过滤，且从 Team 历史入口能够显示该会话。

## Side question 回归

1. 进入已有 chat，确认初始不显示 Side question Tab；执行 `/btw` 后应出现空白 Tab 并自动激活。执行 `/btw 问题` 时，首次 `/api/btw` 请求不得携带旧 `btwId`。
2. BTW idle 时确认 Composer 显示 Send；发送后必须立即切为危险态 Stop。runId/agentKey 尚未注册时 Stop 禁用，注册后启用；点击后在响应返回前显示 loading 且不能重复提交。
3. 分别在 SSE 与全局 WS 主会话模式下点击 BTW Stop，网络面板都应只出现 HTTP `POST /api/interrupt`。返回 `accepted: true` 时 BTW SSE 被本地终止并转 idle；返回 unmatched、其他 rejected 响应或模拟网络错误时仍保持 running、继续接收内容并允许再次点击 Stop。
4. BTW 回答中关闭 Tab，确认没有发送 `/api/interrupt`、当前 SSE 没有被前端 abort，Tab 立即消失并回到 Overview。等待旧流继续返回 identity、事件和 terminal 后，Tab 不得复活；再次 `/btw` 必须是空 transcript、无旧 `btwId` 的新分支，旧流不得写入新分支。
5. 刷新页面前保留一个 running BTW，刷新后确认只对持久化恢复的 run 调用一次 `/api/attach`；正常新发起的 `/api/btw` 不得并发 attach。attach not-found 不应覆盖 live run 状态或使 Stop 消失。
6. 在多个 chat 间分别创建 BTW，确认 Tab 与内容按 chat 隔离。桌面 Tab 关闭和 Copilot BTW 面板关闭都应丢弃对应 chat 的分支；右侧栏最外层关闭按钮只收起，再打开时原 BTW 仍在。

## 边界与非目标
- 手工测试不替代 `make test`。
- 没有可用后端时，只能验证静态页面、路由和构建，无法完成实时协议回归。
- 语音和 Desktop 桥接需要对应运行环境，普通浏览器失败不一定代表前端代码错误。
