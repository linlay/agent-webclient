# 运行参数模型与访问级别

## 当前状态
Composer 的运行参数包含 access level、模型覆盖、reasoning effort、service tier、planning/editing mode 和单次 required skill。通用控件由 `QuerySettingsControls` 承载，Mode 与 Skills 从 Composer “+”菜单选择。

## 核心职责
- 展示并持久化当前会话或当前 agent 的模型选择。
- 为 CODER agent 加载模型选项并处理默认模型覆盖。
- 将 access level、model override 和控制参数随 query payload 发送。
- Mode 按智能体类型显示：`CODER` 提供 Planning，`KBASE` 提供 Editing，普通 Agent 与 Team 不显示 Mode 分组。
- Skills 只展示当前 Agent 已配置且目录可解析的 ready 项，每条消息最多选择一个。
- `requiredSkillKeys` 进入 `/api/query`、SSE/WebSocket 与回放事件；发送进入 query 链路后清理，切换智能体时同步清理。
- 在运行中支持访问级别调整，并同步前端 agents 状态。

## 核心流程
Composer 打开运行参数控件时加载模型选项。发送消息时，`buildControlsParams`、`modelOverride`、`accessLevel`、mode 和 `requiredSkillKeys` 被传入发送事件，最终由 `buildQueryPayload` 写入 `/api/query` 请求。选中 required skill 后如果 @mention 或最终路由智能体与选择来源不一致，前端会阻止发送，避免把约束交给未配置该 skill 的智能体。运行中调整 access level 时调用 data client，并用当前 `RunOwner` 序列化身份：Agent 发送 `agentKey`，编排 Team 仅发送 `teamId`。

## 边界与非目标
- 前端只展示后端返回的模型与权限能力，不自行推断真实权限。
- 非 CODER agent 不展示 CODER 专属模型覆盖入口。
- required skill 是单次、单选约束，Team 不提供选择入口。
- 模型参数只作为请求提示，最终执行语义由后端决定。
