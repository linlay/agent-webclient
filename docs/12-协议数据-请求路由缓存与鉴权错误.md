# 请求路由缓存与鉴权错误

## 当前状态
`src/shared/data/api/routedClient.ts` 根据 endpoint 的 backend WS 能力表在严格 WebSocket request 与静态 HTTP client 之间路由，`query/serverState.ts` 提供轻量缓存，`errors/platformError.ts` 负责错误归一化展示。访问 token 和 Desktop app token 相关逻辑也收敛在数据层。

## 核心职责
- 根据 `transport`、`wsBackends` 和当前 backend mode，在请求前确定 WebSocket 或 HTTP；WS 传输失败不回退。
- 对 GET 端点使用 TTL 和 dedupe 缓存，减少重复拉取。
- 在写操作后按端点前缀失效缓存。
- 统一处理 access token、app auth refresh 和平台错误展示。

## 核心流程
调用方使用 `routedClient` 暴露的函数；函数内部通过 `routeEndpoint` 解析 payload、选择 transport、应用缓存策略。支持当前 backend 的 `auto` endpoint 复用唯一主 WS，连接、断开、超时与业务错误都直接抛出；没有 WS route 的 endpoint 才静态选择 HTTP。

Desktop Frame Port 对 guest 是匿名 transport：guest 不读取或持有 access token，宿主负责完成 Platform 鉴权。Desktop Driver 不执行 WebSocket 握手，也不使用 `allowAnonymous`、close code 或 `WS_DISCONNECTED`；物理断线由宿主报告为 `reconnecting`，永久关闭统一归类为 `DESKTOP_FRAME_PORT_CLOSED`。`allowAnonymous`、握手错误和 `WS_DISCONNECTED` 只属于 Standalone 真实 WebSocket。失败的 GET 请求会清除 in-flight cache Promise，后续只由用户显式 Retry 重新请求，不自动重试，也不回退 HTTP。

## 边界与非目标
- 缓存只服务前端 server-state，不承担离线数据库职责。
- 鉴权 helper 只处理前端 token 携带和刷新，不定义后端权限模型。
- route transport 只用于适合路由的接口；resource、voice-ws、SSE 等特殊传输保持专门路径。
