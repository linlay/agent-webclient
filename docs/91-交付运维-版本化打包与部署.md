# 版本化打包与部署

## 当前状态
仓库只发布 Desktop Program Bundle。版本号来自根目录 `VERSION`，格式为 `vX.Y.Z`。

## 核心职责
- `make release` / `make release-program` 生成 Desktop Program Bundle。
- 保证产物只保留在 `dist/release/`，并带版本化文件名。
- 输出 manifest、`.env.example`、frontend dist 和 Desktop 生命周期脚本。
- 同一构建流程同时生成主应用、轻量静态对话导出模板与内容寻址资产集合；公开分享数据页面不属于 WebClient 产物。

## 核心流程
release 脚本读取版本号并准备隔离构建环境，生产构建前端静态资源，再按 Desktop 目标平台组装压缩包。Desktop 的内置服务同步流程只消费该 Program Bundle。

隔离构建必须携带生产 build 链使用的全部检查器，Unix 与 Windows 原生入口共同校验输入完整性。已有相同版本与平台的发布归档时直接拒绝重建覆盖，选择新的 patch 版本。发布验证比较 Program Bundle、Desktop 同步资源与最终安装/部署资源的实际 HTML、JS、CSS 指纹，而非仅检查 manifest 版本。跨平台生成归档不等于已完成 Windows 原生构建、安装与运行验收。

## 边界与非目标
- Program Bundle 不包含后端入口，也不启动 Node.js 子进程；`deploy.sh` 只初始化 `.env`，Desktop host-managed start 阶段提供 `PORT`、`DESKTOP_APP` 和普通 `/api`、`/ws` 的 `BASE_URL`。HTML 导出的资源域名来自运行时 `CONVERSATION_EXPORT_ASSET_ORIGIN`，不得在模板构建时固定。
- Program manifest 将静态导出模板列为必需路径，运行中的 WebClient Host 通过 `/export/conversation.template.html` 提供它并返回 `Cache-Control: no-store`。`npm run sync:conversation-export` 只把同一次构建的资产集追加到 Tunnel，不再向 Agent Platform 复制模板；同步操作拒绝覆盖同 hash 的不同字节，也不删除历史资产。发布顺序为先部署并探测 Tunnel 资产，再发布引用该 hash 的 WebClient Program 与 Desktop；回滚时必须保留新旧资产集。
- 发布脚本使用 `.env` 或 `.env.example` 完成构建配置；运行参数由 Desktop host-managed start 阶段提供。
- 仓库不维护 Program Bundle 之外的第二套发布产物。
