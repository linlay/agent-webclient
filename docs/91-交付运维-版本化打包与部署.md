# 版本化打包与部署

## 当前状态
仓库只发布 Desktop Program Bundle。版本号来自根目录 `VERSION`，格式为 `vX.Y.Z`。

## 核心职责
- `make release` / `make release-program` 生成 Desktop Program Bundle。
- 保证产物只保留在 `dist/release/`，并带版本化文件名。
- 输出 manifest、`.env.example`、frontend dist 和 Desktop 生命周期脚本。
- 分享渲染包独立构建和发布，不进入普通 WebClient Program Bundle。

## 核心流程
release 脚本读取版本号并准备隔离构建环境，生产构建前端静态资源，再按 Desktop 目标平台组装压缩包。Desktop 的内置服务同步流程只消费该 Program Bundle。

隔离构建工作区会跨发布复用依赖和 Webpack 文件缓存；源码、public 资源与构建配置每次都会从仓库重新同步。依赖缓存按 package manifest、lockfile、`.npmrc`、Node 版本和目标平台自动失效。Windows 默认位于 `%LOCALAPPDATA%/ZenMind/build-cache/agent-webclient`，Unix 默认位于 `${XDG_CACHE_HOME:-$HOME/.cache}/zenmind/build-cache/agent-webclient`；仅在磁盘布局有特殊要求时通过 `AGENT_WEBCLIENT_BUILD_CACHE_DIR` 覆盖缓存根目录。该目录不是发布产物，不应由 Desktop 的 `dist/release` 清理流程删除。

隔离构建必须携带生产 build 链使用的全部检查器，Unix 与 Windows 原生入口共同校验输入完整性。已有相同版本与平台的发布归档时直接拒绝重建覆盖，选择新的 patch 版本。发布验证比较 Program Bundle、Desktop 同步资源与最终安装/部署资源的实际 HTML、JS、CSS 指纹，而非仅检查 manifest 版本。跨平台生成归档不等于已完成 Windows 原生构建、安装与运行验收。

## 边界与非目标
- Program Bundle 不包含后端入口，也不启动 Node.js 子进程；`deploy.sh` 只初始化 `.env`，Desktop host-managed start 阶段提供 `PORT`、`DESKTOP_APP` 和普通 `/api`、`/ws` 的 `BASE_URL`。HTML 导出的资源域名来自运行时 `CONVERSATION_EXPORT_ASSET_ORIGIN`，不得在模板构建时固定。
- `npm run release:conversation-export` 独立生成模板、manifest 和内容寻址资源，并整体替换 Tunnel 当前渲染包；Tunnel 不保留旧 Hash 集合。普通 `npm run build`、`make release` 和 Program manifest 均不包含分享渲染包。更新后先构建和测试 Tunnel，再原子部署同一二进制；本地 HTML 导出通过 `CONVERSATION_EXPORT_ASSET_ORIGIN/assets/conversation-export/conversation.template.html` 获取当前模板。
- 发布脚本使用 `.env` 或 `.env.example` 完成构建配置；运行参数由 Desktop host-managed start 阶段提供。
- 分享渲染包是独立发布产物，源码仍与导出组件共用，避免维护第二套渲染实现。

### 渲染错误诊断与源码映射

渲染错误页的“复制诊断信息”包含错误和可获取的 React 组件堆栈、发生时间、VERSION、Git commit、唯一构建 ID、构建时间、当前 pathname、Desktop/Web 模式、User-Agent，以及最近 40 条点击类型和协议事件类型摘要。连续同类事件合并计数；不采集输入值、可见正文、事件 payload、URL query/hash。错误消息和堆栈按原文保留，分享前应检查其中是否含上游带入的敏感内容。相同报告也会写入浏览器控制台 `[webclient-render-error]`，无自动上传；刷新后内存中的事件摘要不保留。

生产构建将 source map 与 `build.json` 写入 `diagnostics/<build.id>/`，位于 `dist` 之外，不进入 Desktop Program Bundle，JS 不附带 sourceMappingURL。排查时按报告中的 `build.id` 找到同次构建的映射，再将堆栈中的 bundle 文件、行列映射到源码。不要用重新构建的映射替代原始构建产物。

普通 `npm run build` 的 diagnostics 位于仓库根目录；Program 发布使用隔离缓存工作区，diagnostics 位于发布日志中 `BUILD_ROOT` 对应目录下。发布人员需要单独归档对应 diagnostics 目录并按版本保留，避免清理构建缓存后丢失映射。隔离构建准备步骤会同步版本和原仓库 commit；通过发布参数覆盖版本时，诊断版本与发布版本保持一致。
