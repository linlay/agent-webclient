# 版本化打包与部署

## 当前状态
仓库支持 Program Bundle 与 Image Bundle 两种发布形态。Program Bundle 面向 Desktop 托管静态资源，Image Bundle 面向离线 Docker 部署。版本号来自根目录 `VERSION`，格式为 `vX.Y.Z`。

## 核心职责
- `make release` / `make release-program` 生成 Desktop Program Bundle。
- `make release-image` 生成包含镜像 tar、compose 和脚本的 Image Bundle。
- 保证产物只保留在 `dist/release/`，并带版本化文件名。
- 输出 manifest、README.txt、`.env.example`、frontend dist 和部署脚本。
- 同一构建流程同时生成主应用、轻量静态对话导出模板与内容寻址资产集合；公开分享数据页面不属于 WebClient 产物。

## 核心流程
release 脚本读取版本号并准备隔离构建环境，生产构建前端静态资源，再按目标平台组装压缩包。Image release 会构建单架构 Docker 镜像并导出 tar，连同 release compose 和启动脚本一起打包。

## 边界与非目标
- Program Bundle 不包含后端入口，也不启动 Node.js 子进程；`deploy.sh` 只初始化 `.env`，Desktop host-managed start 阶段提供 `PORT`、`DESKTOP_APP` 和普通 `/api`、`/ws` 的 `BASE_URL`。HTML 导出的资源域名来自运行时 `CONVERSATION_EXPORT_ASSET_ORIGIN`，不得在模板构建时固定。
- Program manifest 将静态导出模板列为必需路径。`npm run sync:conversation-export` 把同一次构建的模板 vendored 到 Agent Platform，并把资产集追加到 Tunnel；同步操作拒绝覆盖同 hash 的不同字节，也不删除历史资产。发布顺序固定为先部署并探测 Tunnel 资产，再发布引用该 hash 的 Platform；Desktop 不读取 WebClient Program 内模板，回滚 Platform 时也必须保留新旧资产集。
- Image Bundle 只交付 webclient 静态代理容器，不包含 AGENT API 后端。
- 发布脚本使用 `.env` 或 `.env.example` 完成构建配置，但真实部署值由部署端 `.env` 决定。
